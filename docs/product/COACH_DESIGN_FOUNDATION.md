# BASE11 코치 화면 기본 규칙

> 상태: 보류 — 팀·선수 관리 정책 확정 후 화면에 적용
> 버전: 1.1
> 최종 수정: 2026-08-22
> 1차 사용자: 한국 엘리트 유소년 축구팀 지도자·팀 매니저·스태프
> 적용 범위: Coach Desktop, Coach Mobile

## 1. 기본 방향

BASE11 코치 화면은 한국 유소년 축구팀의 업무용 관리 화면을 기준으로 합니다.

- 장식보다 정보 순서가 먼저 보여야 합니다.
- 중요한 행동과 상태를 바로 구분할 수 있어야 합니다.
- 현재 팀, 시즌, 스쿼드와 세션을 항상 확인할 수 있어야 합니다.
- 사무실의 큰 화면과 운동장의 작은 화면에서 모두 읽을 수 있어야 합니다.

축구 게임, 팬 서비스, 피트니스 소비자 앱처럼 보이지 않아야 합니다. 잔디 무늬, 네온 색상, 과한 그라데이션, 트로피·불꽃 같은 장식과 승패를 과장하는 표현은 사용하지 않습니다.

## 2. 디자인 판단의 기준 사용자

우선순위는 다음과 같습니다.

1. 감독·헤드코치: 오늘의 결정, 주간 계획, 승인과 예외 확인
2. 스쿼드·포지션 코치: 배정 세션 준비, 선수 상태, 현장 메모와 피드백
3. 팀 매니저: 일정, 대상자, 장소, 전달과 누락 관리
4. 피지컬·메디컬 스태프: 부하, 제한, 복귀 상태와 데이터 품질 확인

선수와 학부모는 현재 디자인 최적화 대상이 아닙니다. 다만 코치 화면에서 공개 범위와 수신 대상을 안전하게 관리할 수 있어야 하며, 내부 정보가 외부로 노출되지 않게 합니다.

## 3. 핵심 디자인 원칙

### 3.1 결정이 필요한 것부터

정상 상태를 반복해서 보여주기보다 결석 가능성, 참여 제한, 승인 대기, 데이터 누락과 일정 충돌을 먼저 보여줍니다. 정상 항목은 요약하거나 접습니다.

### 3.2 맥락을 잃지 않게

팀, 시즌, 스쿼드, 날짜와 현재 세션을 주요 화면 상단에서 확인할 수 있어야 합니다. 범위를 바꾸면 어떤 데이터와 대상이 달라지는지 바로 알려줍니다.

### 3.3 한 화면에 한 가지 주 행동

페이지마다 가장 중요한 기본 행동은 하나만 강조합니다. 나머지는 보조 버튼, 더보기 메뉴 또는 행 단위 행동으로 낮춥니다.

### 3.4 카드보다 구조

모든 내용을 카드로 감싸지 않습니다. 페이지 구획은 제목, 여백, 얇은 선으로 만들고 카드는 독립적인 결정 묶음에만 사용합니다.

### 3.5 색보다 문장

상태는 색만으로 구분하지 않습니다. 아이콘 또는 짧은 문장과 함께 표시합니다. 초록색은 정상·완료, 주황색은 확인 필요, 빨간색은 참여 불가·오류·위험에만 사용합니다.

### 3.6 모바일은 축소판이 아닌 현장 도구

데스크톱은 계획·검토·비교에, 모바일은 확인·변경·빠른 기록에 최적화합니다. 큰 표를 모바일에 그대로 줄이지 않고 우선순위 카드와 행 단위 작업으로 바꿉니다.

## 4. 컬러 시스템

화면의 권장 비율은 `중립색 80% / 잉크·파랑 15% / 상태색 5% 이하`입니다.

| 역할 | 토큰 | 값 | 사용처 |
| --- | --- | --- | --- |
| 핵심 잉크 | `ink` | `#17202B` | 제목, 본문, 기본 주 행동 |
| BASE11 블루 | `brand` | `#1769E0` | 선택, 링크, 포커스, 현재 위치 |
| 강한 블루 | `brandStrong` | `#0F4FB8` | 눌림, 강조 선택 |
| 블루 배경 | `brandSoft` | `#EAF2FF` | 선택된 행, 정보 강조 |
| 캔버스 | `canvas` | `#F4F6F8` | 앱 배경 |
| 표면 | `surface` | `#FFFFFF` | 패널, 표, 입력 영역 |
| 보조 텍스트 | `muted` | `#667085` | 설명, 메타데이터 |
| 약한 텍스트 | `subtle` | `#98A2B3` | 비활성 보조 정보 |
| 경계선 | `line` | `#D8DEE6` | 입력, 표, 구획 |
| 약한 경계선 | `lineSoft` | `#EAEEF2` | 행 구분 |
| 완료·정상 | `success` | `#147A4B` | 완료, 참가 가능 |
| 확인 필요 | `warning` | `#B85C00` | 누락, 지연, 주의 |
| 불가·위험 | `danger` | `#C93F36` | 참여 불가, 삭제, 오류 |
| 참고 상태 | `info` | `#5B5BD6` | 동기화, 시스템 정보 |

규칙:

- 잔디색·형광색을 브랜드색으로 사용하지 않습니다.
- 초록색 배지를 정상 항목마다 붙이지 않습니다. 정상은 조용하게, 예외만 두드러지게 합니다.
- 텍스트와 배경의 대비는 WCAG AA를 충족합니다.
- 그래프에서도 빨강·초록만으로 계열을 구분하지 않습니다.

## 5. 타이포그래피

### 5.1 기본 서체

`Pretendard Variable`을 웹과 모바일의 1순위 서체로 사용합니다. 한국어와 영문·숫자가 섞인 운영 화면에서 균일한 인상을 주고, 가변 폰트 한 파일로 필요한 굵기를 운용하기 좋습니다.

```css
font-family: "Pretendard Variable", Pretendard, "Noto Sans KR",
  "Apple SD Gothic Neo", "Malgun Gothic", system-ui, sans-serif;
```

- 웹: 필요한 한글 서브셋 WOFF2를 직접 호스팅합니다.
- Flutter: 폰트 파일을 앱 자산으로 포함하고 테마에서 명시합니다.
- 대체 서체: `Noto Sans KR`; 운영체제 기본 한글 고딕 순으로 폴백합니다.
- 숫자 표와 시간에는 별도 영문 폰트를 섞지 않고 `font-variant-numeric: tabular-nums`를 사용합니다.

### 5.2 크기와 굵기

| 역할 | 데스크톱 | 모바일 | 굵기 | 행간 |
| --- | ---: | ---: | ---: | ---: |
| 페이지 제목 | 28px | 24px | 700 | 1.30 |
| 섹션 제목 | 20px | 19px | 700 | 1.40 |
| 카드·패널 제목 | 16px | 16px | 600 | 1.45 |
| 본문 | 15px | 15px | 400 | 1.55 |
| 본문 강조 | 15px | 15px | 600 | 1.55 |
| 표·목록 | 14px | 14px | 400/500 | 1.45 |
| 라벨·버튼 | 13px | 14px | 600 | 1.40 |
| 보조 정보 | 12px | 12px | 400/500 | 1.40 |

규칙:

- 일반 화면에서 12px 미만 글자를 사용하지 않습니다.
- 800·900 굵기를 사용하지 않습니다. 굵기보다 크기, 여백과 위치로 위계를 만듭니다.
- 제목 자간은 `-0.02em`, 본문은 `-0.01em` 이내로만 조정합니다.
- 대문자 영문 라벨과 과도한 약어를 피합니다.

## 6. 공간, 형태와 밀도

- 기본 단위: 4px
- 화면 좌우 여백: 데스크톱 24~32px, 모바일 16px
- 섹션 간격: 32px
- 패널 내부 여백: 16~20px
- 목록 행 높이: 기본 48px, 복합 정보 56~64px
- 최소 터치 영역: 데스크톱 44×44px, 모바일 48×48px
- 모서리: 작은 요소 6px, 입력·버튼 10px, 큰 패널 14px
- 그림자: 떠 있는 메뉴·모달에만 사용하고 일반 패널은 1px 경계선으로 구분

둥근 모서리는 친근함을 더하는 수준에서만 사용합니다. 알약 모양은 상태, 필터와 짧은 선택에만 허용합니다.

## 7. 레이아웃 규칙

### 데스크톱

- 좌측 내비게이션 232~248px
- 본문 최대 폭 1440px, 데이터 표는 필요 시 폭을 모두 사용
- 상단에는 현재 팀·시즌·스쿼드 범위와 저장 상태를 유지
- 제목 아래 첫 영역에는 오늘의 결정 또는 이 화면의 핵심 요약을 배치
- 상세 정보는 우측 패널 또는 별도 상세 화면으로 열어 목록 맥락을 보존

### 모바일

- 한 열 구조와 16px 좌우 여백
- 오늘의 세션, 참여 제한, 빠른 메모를 첫 화면에 배치
- 주 행동은 필요할 때 하단 고정 영역에 배치
- 복잡한 생성·대량 편집은 데스크톱으로 안내하고, 현장에 필요한 변경은 막지 않음

## 8. 컴포넌트 규칙

### 버튼

- 주 버튼: 잉크색 배경, 페이지당 하나
- 보조 버튼: 흰 배경과 경계선
- 링크 행동: BASE11 블루
- 위험 행동: 기본 상태에서는 중립적으로 두고 확인 단계에서 빨간색 사용
- 라벨은 `저장`, `게시`, `참가자 확정`처럼 동사로 시작

### 상태 배지

기본 상태 체계는 네 가지입니다.

| 의미 | 예시 문구 | 표현 |
| --- | --- | --- |
| 완료·가능 | 참가 가능, 게시 완료 | 초록 + 문구 |
| 확인 필요 | GPS 누락, 승인 대기 | 주황 + 문구 |
| 불가·위험 | 참여 불가, 충돌 | 빨강 + 문구 |
| 진행·참고 | 동기화 중, 임시 저장 | 보라/파랑 + 문구 |

### 표와 목록

- 코치 데스크톱의 기본 비교 수단은 표입니다.
- 선수 이름과 핵심 상태 열은 스크롤 시 고정할 수 있게 합니다.
- 체크박스는 실제 일괄 행동이 있을 때만 노출합니다.
- 숫자는 우측 정렬하고 단위를 헤더 또는 값에 일관되게 표시합니다.
- 기본 정렬 기준과 적용된 필터를 항상 확인할 수 있어야 합니다.

### 입력과 저장

- 자동 저장 여부를 `저장 중`, `방금 저장됨`, `저장 실패`처럼 명시합니다.
- 유효성 오류는 필드 가까이에서 원인과 해결 방법을 함께 설명합니다.
- 삭제, 게시 취소와 수신자 변경은 영향 대상을 확인한 뒤 실행합니다.

## 9. 아이콘, 사진과 움직임

- 아이콘: 18~20px 단색 선형 아이콘, 같은 세트 사용
- 아이콘만 있는 버튼은 접근성 이름과 툴팁 제공
- 선수 사진과 팀 엠블럼은 식별에 도움이 될 때만 사용
- 장식용 경기장·선수 스톡 사진은 운영 화면에서 사용하지 않음
- 전환 120~180ms, 상태 변화 180~240ms
- 숫자 카운트업, 과한 슬라이드, 축하 애니메이션은 사용하지 않음

## 10. 한국어 제품 문장 규칙

- 화면 제목은 명사형: `주간 계획`, `선수단 상태`, `공지 작성`
- 행동은 동사형: `세션 만들기`, `참가자 확정`, `공지 게시`
- 감성적인 슬로건, 불필요한 영어 이름과 기능을 과장하는 문구를 화면에 사용하지 않음
- `스마트`, `인사이트`, `솔루션`, `최적화`, `자동 추천`처럼 의미가 모호한 표현 대신 실제 작업을 씀
- 오류는 책임을 사용자에게 돌리지 않음: `저장하지 못했습니다. 연결을 확인한 뒤 다시 시도해 주세요.`
- 날짜: `8월 22일(토)`; 시간이 핵심이면 `8월 22일(토) 17:00`
- 사람 수: `24명 중 3명 확인 필요`
- 약어는 현장에서 익숙한 경우만 사용하고 첫 등장에 설명: `RPE(자각 운동 강도)`
- `성공`, `실패`보다 `완료`, `확인 필요`, `참여 불가`처럼 운영 판단에 가까운 말을 사용

## 11. 대표 화면의 정보 우선순위

코치 대시보드는 다음 순서로 보여줍니다.

1. 오늘 반드시 결정할 항목
2. 다음 세션과 경기까지 남은 시간
3. 참여 제한·부상·컨디션 예외 선수
4. 스태프 승인·입력·데이터 누락
5. 이번 주 훈련 계획과 부하 흐름
6. 전체 정상 현황과 과거 기록

첫 화면의 목표는 많은 정보를 보여주는 것이 아니라 **지도자가 1분 안에 오늘의 우선순위를 정하게 하는 것**입니다.

## 12. 적용 순서

1. 공통 컬러·간격·모서리·타이포 토큰 통합
2. 웹과 모바일의 Pretendard 실제 포함 및 800 이상 굵기 제거
3. 코치 대시보드, 일정, 세션 운영에 새 위계 적용
4. 표·상태·저장·빈 화면·오류 패턴 통합
5. 야외 시인성, 작은 화면, 한 손 조작과 색각 접근성 검증

새 화면을 만들 때 이 문서와 공통 토큰을 우선 적용합니다. 기존 화면은 코치 핵심 흐름 순서대로 교체하며, 화면마다 별도 색상·폰트·모서리를 추가하지 않습니다.
