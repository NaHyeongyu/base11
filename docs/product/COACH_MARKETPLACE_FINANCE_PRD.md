# 지도자 세션 마켓·팀 재무 관리 기획서

> 상태: 정책 초안 0.1
> 최종 수정: 2026-08-23
> 기준 사용자: 한국 유소년 축구팀 지도자·팀 매니저
> 상위 문서: [BASE11 제품 기획서](./PRODUCT_SPEC.md)
> 연결 기능: [훈련·경기 등록 및 관리 기능 기획서](./TRAINING_MATCH_OPERATIONS_PRD.md)

## 1. 결정 요약

BASE11에 다음 두 기능을 추가합니다.

1. `세션 마켓`: 지도자가 직접 만든 훈련 세션 자료를 다른 지도자에게 판매하고, 구매한 지도자가 자신의 일정과 훈련 템플릿으로 복사해 사용하는 기능
2. `팀 재무`: 팀의 수입, 지출, 예산, 증빙, 승인과 월·시즌 마감을 관리하는 기능

기존 핵심 내비게이션인 `오늘 · 선수단 · 일정`은 유지합니다. 두 기능은 고급 운영 업무이므로 프로필 위의 보조 진입점인 `운영센터` 안에 둡니다.

```text
오늘
선수단
일정

운영센터
  ├─ 세션 마켓
  ├─ 내 판매
  ├─ 팀 재무
  └─ 정산·세금 정보
```

- 데스크톱: 사이드바 하단의 `운영센터`
- 모바일: 하단 3개 메뉴는 유지하고 전체 메뉴에서 진입
- 세션 마켓은 지도자 개인 범위, 팀 재무는 팀·시즌 범위
- 판매 수익을 팀 재무에 연결할지는 사용자가 건별 또는 기본값으로 정함

## 2. 제품 경계

### 2.1 세션 마켓 MVP에 포함

- 훈련 세션 템플릿 판매·구매
- 미리보기와 상세 설명
- 가격 설정, 결제, 구매 내역
- 구매 콘텐츠를 내 훈련 템플릿으로 복사
- 판매 현황과 정산 예정 금액
- 구매자 리뷰와 신고
- 저작권, 개인정보, 환불 상태 관리

### 2.2 세션 마켓 MVP에서 제외

- 선수 개인정보, 의료 정보, 원본 GPS 데이터 판매
- 얼굴이 식별되는 미성년 선수 영상의 기본 판매
- 실시간 코칭, 오프라인 강습 예약
- 구독 상품, 경매, 판매자 간 메시지
- 구매 콘텐츠의 재판매

### 2.3 팀 재무 MVP에 포함

- 수입·지출 등록
- 카테고리와 프로젝트·대회별 분류
- 예산 대비 사용액
- 영수증·계약서 증빙 연결
- 지출 요청, 승인, 지급 완료
- 월별·시즌별 현황과 CSV 내보내기
- 마켓 판매 수익·구매 비용 자동 연결
- 변경·취소·반제 이력

### 2.4 팀 재무 MVP에서 제외

- 은행 계좌 자동 이체와 오픈뱅킹
- 선수·학부모 회비 청구와 자동 수납
- 급여 계산과 세금 신고 대행
- 세금계산서 직접 발행
- 법정 회계장부를 대체한다는 표현

초기 재무 기능은 지도자의 운영 기록과 내부 결재를 돕는 도구입니다. 회계·세무 신고 결과를 확정하는 서비스로 제공하지 않습니다.

## 3. 핵심 사용자와 권한

| 역할 | 세션 마켓 | 팀 재무 |
| --- | --- | --- |
| 감독·헤드코치 | 구매, 판매, 판매 승인 | 전체 조회, 예산 승인, 월·시즌 마감 |
| 코치 | 구매, 본인 자료 판매 | 본인 지출 요청, 허용된 예산 조회 |
| 팀 매니저 | 팀 공용 구매 관리 | 수입·지출 등록, 증빙 확인, 지급 처리 |
| 재무 관리자 | 접근 선택 | 전체 조회, 승인, 반제, 내보내기 |
| 피지컬·메디컬 | 전문 자료 구매 가능 | 본인 지출 요청만 기본 허용 |

권한 원칙:

- 판매자는 반드시 성인 지도자 계정이어야 합니다.
- 팀 재무는 팀별 권한을 별도로 부여합니다.
- 지출 등록자와 최종 승인자를 분리할 수 있어야 합니다.
- 승인된 거래는 삭제하지 않고 반제 거래를 만들어 취소합니다.
- 정산 계좌와 세금 정보는 판매자 본인과 제한된 운영자만 열람합니다.

## 4. 세션 마켓 상품 정책

### 4.1 MVP 상품 단위

MVP에서는 `훈련 세션 템플릿`만 판매합니다.

한 상품은 다음을 포함합니다.

- 대상 연령: U10, U12, U15, U18 등
- 권장 인원과 최소·최대 인원
- 훈련 목적과 적용 상황
- 총 시간과 블록별 시간
- 구장 크기와 배치
- 필요 장비
- 전체 강도와 권장 RPE
- 블록별 진행 방법
- 코칭 포인트
- 자주 발생하는 문제와 수정 방법
- 안전·부상 유의사항
- 익명화된 도식 또는 판매 권한이 확인된 이미지·영상
- 미리보기 범위
- 버전과 최종 수정일

구매 후에는 BASE11의 `TrainingTemplate`으로 복사됩니다. 판매자가 원본을 수정해도 이미 구매한 템플릿은 자동으로 바뀌지 않습니다.

### 4.2 후속 상품

- 1주 마이크로사이클 패키지
- 포지션별 세션 묶음
- 시즌 준비 프로그램
- 분석·코칭 문서

후속 상품은 MVP 거래·환불·저작권 정책이 안정된 뒤 추가합니다.

### 4.3 판매 금지 정보

다음 정보가 포함되면 게시할 수 없습니다.

- 선수 이름, 연락처, 생년월일, 학교, 등번호와 얼굴의 결합 정보
- 부상, 통증, 상담과 의료 정보
- 원본 GPS·피지컬 측정 데이터
- 특정 선수를 추정할 수 있는 경기·상담 메모
- 상대 팀의 비공개 전술 자료
- 제3자가 권리를 가진 영상, 이미지, 문서
- 연락처, 계좌번호 등 플랫폼 밖 거래를 유도하는 정보

선수 사례가 필요하면 `U15 중앙 미드필더 A`처럼 익명화하고 수치를 범위로 바꿉니다. 미성년 선수가 식별되는 영상은 MVP에서 판매 자료로 받지 않는 것을 기본 정책으로 합니다.

### 4.4 라이선스

구매자는 다음 권리를 가집니다.

- 본인이 지도하는 팀 내부에서 사용
- 인원, 시간, 블록과 코칭 포인트 수정
- 자신의 세션 일정으로 복사

구매자는 다음을 할 수 없습니다.

- 원본 또는 수정본 재판매
- 공개 커뮤니티·자료실에 원본 배포
- 판매자 이름을 제거하고 본인 창작물로 표시
- 한 팀 라이선스를 여러 독립 기관에서 공유

MVP 기본 라이선스는 `구매 지도자 1명 + 소속 팀 1개`입니다. 다기관 라이선스는 후속 상품으로 분리합니다.

## 5. 세션 마켓 흐름

### 5.1 판매

```text
내 훈련에서 템플릿 선택
  → 판매용 복사본 생성
  → 설명·가격·미리보기 입력
  → 개인정보·저작권 자동 점검
  → 판매자 확인
  → 운영 검토
  → 게시
  → 판매·리뷰
  → 정산 가능
```

판매 상태:

```text
작성 중 → 검토 요청 → 수정 필요 / 승인 → 판매 중 → 판매 중지 → 보관
```

- 판매용 상품은 실제 팀 세션과 별도 복사본으로 만듭니다.
- 실제 참가자, 선수 메모와 GPS 연결은 복사 대상에서 항상 제외합니다.
- 판매 중인 버전은 수정하지 않고 새 버전을 게시합니다.
- 신고 또는 권리 분쟁 중에는 새 판매와 정산을 일시 보류할 수 있습니다.

### 5.2 구매

```text
검색·필터
  → 상품 상세·미리보기
  → 라이선스·환불 조건 확인
  → 결제
  → 구매 완료
  → 내 템플릿으로 복사
  → 일정에서 사용
  → 검증된 구매 리뷰
```

검색 필터:

- 연령
- 훈련 목적
- 인원
- 시간
- 강도
- 구장 크기
- 장비
- 가격
- 평점과 판매량

개인화 추천은 MVP에서 제외합니다. 기본 정렬은 `관련도`, `최근 업데이트`, `평점`, `판매량`을 명시적으로 제공합니다.

## 6. 가격·결제·환불·정산 정책

### 6.1 가격

- 판매자가 허용 범위 안에서 원화 가격을 설정합니다.
- 결제 화면에 상품 가격, 플랫폼 수수료 포함 여부와 최종 결제액을 표시합니다.
- 할인은 운영자가 만든 쿠폰만 MVP에서 지원합니다.
- 판매자가 상품별 임의 외부 결제를 유도할 수 없습니다.

### 6.2 디지털 콘텐츠 제공 시점

결제 직후 바로 전체 콘텐츠를 열지 않고 다음 순서로 처리합니다.

1. 상품 설명과 일부 블록을 결제 전에 미리보기로 제공
2. 결제 직전에 디지털 콘텐츠 제공 시작과 환불 제한 가능성을 별도로 고지
3. 사용자가 확인한 뒤 결제
4. 결제 승인 후 전체 열람과 템플릿 복사 허용
5. 최초 열람·복사 시각을 감사 기록으로 저장

환불 가능 여부를 단순히 `다운로드했으니 환불 불가`로 처리하지 않습니다. 표시·광고와 다른 내용, 파일 결함, 이용 불가와 법령상 철회 사유를 별도로 처리합니다.

### 6.3 제품 환불 상태

```text
환불 요청 → 자동 가능 / 운영 검토 → 승인 / 거절 → 결제 취소 → 판매·재무 반제
```

- 전체 콘텐츠 제공 전 취소: 자동 환불 대상
- 전체 콘텐츠 제공 후 단순 변심: 사전 고지, 미리보기 제공과 관련 법령을 기준으로 판정
- 설명과 다른 상품, 심각한 누락·오류: 운영 검토 후 환불 가능
- 중복 결제: 자동 확인 후 환불
- 결제 도용·분쟁: 해당 주문, 판매자 정산과 연결 거래 보류

구체적인 기간과 예외는 결제사·법무 검토 후 정책 설정값으로 관리하고 코드에 숫자를 고정하지 않습니다.

### 6.4 판매자 정산

정산 금액은 다음 항목을 분리해 표시합니다.

```text
총 판매액
  - 결제 수수료
  - 플랫폼 수수료
  - 환불·분쟁 보류액
  - 법령·판매자 유형에 따른 세금 관련 금액
  = 정산 예정액
```

- 첫 정산 전에 본인 확인, 판매자 유형과 정산 계좌 확인
- 정산 가능일은 주문별 `settlement_available_at`으로 저장
- 정산 주기와 보류 기간은 운영 정책 설정으로 관리
- 세금 처리 방식을 모든 판매자에게 같은 비율로 고정하지 않음
- 개인, 개인사업자, 법인에 따라 필요한 정보와 증빙을 분리
- 정산 완료 후 금액을 직접 수정하지 않고 조정·반제 내역 추가

## 7. 팀 재무 정보 구조

### 7.1 요약 화면

첫 화면에는 다음 네 항목만 표시합니다.

- 현재 사용 가능 금액
- 이번 달 수입
- 이번 달 지출
- 승인·증빙 확인 필요 건수

아래에는 최근 거래와 예산 초과 항목을 우선 표시합니다. 전체 차트보다 처리할 항목이 먼저입니다.

### 7.2 거래 유형

수입 예시:

- 구단·학교 지원금
- 대회 지원금
- 스폰서·후원금
- 세션 마켓 판매 수익
- 기타 운영 수입

지출 예시:

- 구장 대관
- 대회 참가비
- 원정 교통·숙박
- 장비·유니폼
- 식비·간식
- 의료·재활
- 데이터·소프트웨어
- 세션 마켓 구매
- 기타 운영비

선수·학부모 회비는 후속 수납 기능이 확정되기 전까지 일반 수입으로 직접 등록만 허용하고 개인별 미납 관리 화면은 만들지 않습니다.

### 7.3 거래 상태

```text
작성 중 → 승인 요청 → 승인 / 반려 → 지급 예정 → 지급 완료 → 대사 완료
```

- 작은 지출은 권한별 자동 승인 한도를 설정할 수 있습니다.
- 승인 요청 후 금액·거래처·증빙 변경 시 다시 승인을 받습니다.
- 지급 완료 거래는 삭제하지 않습니다.
- 잘못된 거래는 원거래를 유지하고 반제 거래를 연결합니다.
- 같은 영수증 번호, 금액, 날짜와 거래처가 겹치면 중복 가능성을 경고합니다.

### 7.4 예산

예산 범위:

- 시즌 전체
- 월
- 대회·전지훈련 프로젝트
- 비용 카테고리

표시 기준:

- 예산
- 승인된 지출
- 지급 완료
- 남은 예산
- 승인 대기 금액

승인 대기 금액을 남은 예산에서 숨기지 않습니다. `남은 예산`과 `승인 대기 반영 후 예상 잔액`을 함께 보여줍니다.

### 7.5 증빙

- 영수증, 세금계산서, 계약서, 이체 확인증
- 원본 파일과 업로드 시각 보존
- 거래당 복수 증빙 허용
- 주민등록번호, 계좌번호 등 민감 정보 마스킹 안내
- 파일 교체 시 이전 파일 이력 보존
- 증빙 없음 사유와 보완 기한 기록

## 8. 팀 재무 흐름

### 8.1 지출 요청

```text
금액·거래처·카테고리 입력
  → 팀·시즌·프로젝트 연결
  → 증빙 첨부
  → 예산 확인
  → 승인 요청
  → 승인 / 반려
  → 지급 완료
  → 월말 대사
```

### 8.2 수입 등록

```text
수입 유형·금액 입력
  → 입금일·거래처 연결
  → 증빙 첨부
  → 확인
  → 입금 완료
  → 월말 대사
```

### 8.3 월·시즌 마감

```text
미승인·미지급·증빙 누락 확인
  → 거래 대사
  → 월 마감
  → 보고서 내보내기
```

- 마감 월은 일반 사용자가 수정할 수 없습니다.
- 마감 취소는 재무 관리자 권한과 사유가 필요합니다.
- 시즌 종료 시 거래와 증빙은 읽기 전용으로 보관합니다.
- 다음 시즌으로 넘길 금액은 `기초 잔액` 거래로 생성하고 이전 시즌 원장을 연결합니다.

## 9. 마켓과 재무 연결

### 9.1 판매 수익

```text
주문 결제
  → 정산 예정
  → 환불·분쟁 기간 확인
  → 정산 확정
  → 팀 재무 수입 거래 생성
  → 계좌 입금 대사
```

연결 시 총 판매액, 수수료, 세금 관련 금액과 순정산액을 각각 보존합니다. 재무 화면에는 순입금만 표시하지 않고 계산 근거를 열 수 있어야 합니다.

### 9.2 콘텐츠 구매

```text
팀 결제 수단으로 구매
  → 팀 재무 지출 초안 생성
  → 영수증 자동 연결
  → 승인 정책 확인
  → 지급 완료
```

개인 결제로 구매한 상품을 팀 비용으로 청구하려면 별도의 지출 요청을 만듭니다.

## 10. 예외 처리

| 상황 | 처리 |
| --- | --- |
| 결제 성공, 콘텐츠 복사 실패 | 주문은 유지하고 복사를 재시도하며 중복 템플릿 생성 방지 |
| 결제 승인 응답 중복 | 결제사 거래 ID로 멱등 처리 |
| 판매자가 상품 삭제 | 기존 구매자는 구매 버전을 계속 사용, 신규 판매만 중지 |
| 상품 신고·저작권 분쟁 | 신규 판매·정산 보류, 기존 구매자 접근은 사안별 운영 판단 |
| 선수 개인정보 발견 | 즉시 비공개, 정산 보류, 판매자 수정 또는 영구 차단 검토 |
| 환불 후 이미 복사된 템플릿 | 신규 사용 제한 정책을 고지하고 감사 기록 보존, 기술적 회수 범위는 법무 검토 |
| 정산 계좌 오류 | 정산 실패 상태 유지, 금액을 소멸시키지 않고 재시도 |
| 영수증 중복 | 삭제하지 않고 중복 후보로 묶어 재무 관리자 확인 |
| 승인 후 금액 변경 | 기존 승인 무효, 재승인 |
| 마감 월 거래 발견 | 다음 달 조정 거래로 기록하거나 권한 있는 마감 취소 |
| 시즌 전환 | 이전 원장 읽기 전용 보관, 기초 잔액만 다음 시즌으로 연결 |
| 팀 탈퇴·권한 해제 | 과거 승인·거래 작성자 이름과 이력 보존, 신규 접근 차단 |

## 14. MVP 완료 기준

### 세션 마켓

- 실제 세션의 선수·GPS·의료 정보 없이 판매용 버전을 만들 수 있음
- 구매 전 상품 구성과 일부 콘텐츠를 확인할 수 있음
- 결제 후 같은 상품이 중복 구매·복사되지 않음
- 구매 상품을 3번 이내 동작으로 내 템플릿에 추가할 수 있음
- 환불이 주문, 판매 수익과 재무 거래에 일관되게 반영됨
- 판매자가 총 판매액, 보류액, 수수료와 정산 예정액을 구분해 볼 수 있음

### 팀 재무

- 1분 안에 기본 지출과 증빙을 등록할 수 있음
- 승인 대기와 예산 초과가 첫 화면에 표시됨
- 승인 완료 거래를 삭제할 수 없고 반제로만 취소할 수 있음
- 월별 수입·지출과 증빙 누락을 내보낼 수 있음
- 시즌 마감 후 이전 원장을 훼손하지 않고 다음 시즌 기초 잔액을 연결할 수 있음

## 15. 구현 순서

### 1단계: 기반

- 운영센터 진입
- 마켓 상품·버전·라이선스 모델
- 재무 원장·거래·권한 모델
- 개인정보 제거 규칙

### 2단계: 거래 없는 사용성 검증

- 무료 세션 공유와 내 템플릿 복사
- 수입·지출·예산·증빙
- 재무 승인 흐름

### 3단계: 유료 판매

- 결제
- 환불
- 판매자 확인
- 정산과 세금 정보
- 마켓 거래의 재무 자동 연결

### 4단계: 운영 고도화

- 신고·분쟁 운영 도구
- 판매 분석
- 마이크로사이클 패키지
- 은행 대사 연동 검토

무료 공유와 재무 원장을 먼저 검증하고 유료 결제·정산을 붙입니다. 결제부터 구현해 상품 품질, 개인정보와 환불 운영이 뒤늦게 결정되는 순서를 피합니다.

## 16. 법무·세무 검토 체크

이 문서의 운영 정책은 제품 설계 기준이며 법률·세무 자문을 대신하지 않습니다. 출시 전 다음 항목을 전문가와 결제대행사 기준으로 확정합니다.

- 디지털 콘텐츠 제공 시작 전 청약철회 제한 고지와 미리보기 제공 방식
- 표시·광고와 다른 콘텐츠의 환불 처리
- 통신판매업자·통신판매중개자 역할과 고지 의무
- 판매자 유형별 소득 분류, 원천징수와 지급명세서 제출 주체
- 판매 수수료와 부가가치세 표시 방식
- 미성년 선수 영상·개인정보의 판매 금지와 신고 대응
- 정산 계좌 본인 확인, 부정거래와 자금세탁 방지 범위
- 거래·정산·증빙 데이터 보관 기간
