# 선수 생애주기·시즌 전환·진학 데이터 정책

> 상태: 기준안 1.0
> 최종 수정: 2026-08-23
> 1차 사용자: 감독, 팀 매니저, 구단 관리자
> 적용 범위: 다음 시즌 전환, 졸업, 진학·이적, 구단 간 데이터 인계, 보관·파기
> 상위 정책: [팀·선수 등록 및 관리 정책](./TEAM_PLAYER_MANAGEMENT_POLICY.md)
> 예외 기준: [팀·선수 관리 예외 처리 정책](./TEAM_PLAYER_MANAGEMENT_EXCEPTION_POLICY.md)
> 시각 흐름: [Figma FigJam 시즌 전환·졸업·진학 데이터 흐름](https://www.figma.com/board/WcsxYYqcQRPXUHgKrcnQUp)

## 1. 목적

선수의 시즌, 팀과 학교가 바뀌어도 같은 사람의 기록은 이어지게 하되, 이전 팀의 정보가 새 학교에 임의로 공개되지 않도록 기준을 정합니다.

이 문서는 다음 질문에 답합니다.

- 다음 시즌에 어떤 정보를 이어 쓰고 무엇을 다시 확인할 것인가
- 졸업한 선수는 현재 명단과 과거 기록에서 어떻게 보일 것인가
- 새 학교는 이전 학교가 확인한 어떤 정보를 볼 수 있는가
- 선수 또는 법정대리인의 동의를 어떻게 확인할 것인가
- 이전 학교 기록과 새 학교 기록을 누가 수정할 수 있는가
- 탈퇴·졸업·이적 후 개인정보를 언제까지 어떻게 보관할 것인가

## 2. 확정 원칙

1. 선수 한 명은 BASE11 내부에서 하나의 `선수 식별자`를 사용합니다.
2. 다른 구단은 선수 식별자를 이름이나 생년월일로 검색할 수 없습니다.
3. 같은 팀의 다음 시즌은 선수 복사가 아니라 새 `시즌 등록` 생성입니다.
4. 지난 시즌 기록은 새 시즌 값으로 덮어쓰지 않고 읽기 전용 이력으로 남깁니다.
5. 졸업은 선수 삭제가 아니라 팀 등록 종료와 `졸업생` 상태 전환입니다.
6. 다른 학교·구단에는 선수 또는 법정대리인이 동의한 인계 범위만 제공합니다.
7. 새 학교는 이전 학교가 만든 원본 기록을 수정할 수 없습니다.
8. 새 학교에서 만든 시즌·측정·평가 기록은 이전 학교가 볼 수 없습니다.
9. 의료 정보, 비공개 지도자 메모와 징계성 내부 기록은 기본 인계 대상에서 제외합니다.
10. 모든 인계 데이터에는 출처, 기록일, 확인일과 제공 범위를 표시합니다.
11. 동의 철회, 인계 만료와 목적 달성 시 접근을 중단하고 보관 정책에 따라 삭제·분리·익명화합니다.
12. 동일 이름, 학교 입력 또는 구두 확인만으로 구단 간 기록을 자동 연결하지 않습니다.

## 3. 데이터 구분

```text
선수 식별 정보
├─ 구단별 선수 프로필
│  ├─ 팀 등록
│  │  └─ 시즌 등록
│  ├─ 일정·참가·측정·평가 기록
│  └─ 연락·의료·지도자 메모
└─ 데이터 인계 건
   ├─ 동의 기록
   ├─ 제공 범위
   ├─ 출신팀 확인본
   └─ 수신팀 열람 권한
```

### 3.1 선수 식별 정보

- 같은 사람의 기록을 연결하기 위한 BASE11 내부 식별자입니다.
- 다른 구단에는 내부 ID를 노출하지 않습니다.
- 다른 구단의 검색·자동 완성·중복 후보에 사용하지 않습니다.
- 유효한 인계 건을 승인할 때만 기존 식별자와 연결합니다.

### 3.2 구단별 선수 프로필

- 해당 구단이 수집·확인한 이름, 연락처, 학교, 축구 기본 정보와 운영 기록입니다.
- 다른 구단이 같은 선수를 등록해도 자동으로 공개되지 않습니다.
- 값마다 `수집 구단`, `기록 시각`, `확인 시각`, `수정자`를 남깁니다.

### 3.3 시즌 등록

- 시즌, 공식 스쿼드, 학년, 등번호, 주 포지션과 등록 상태를 보관합니다.
- 시즌마다 새로 생성하며 선수 원본은 복제하지 않습니다.
- 종료된 시즌 등록은 읽기 전용입니다.

### 3.4 인계 확인본

- 출신팀이 확인하고 선수 또는 법정대리인이 제공에 동의한 시점의 읽기 전용 묶음입니다.
- 새 학교는 확인본의 값을 자체 현재 프로필에 반영할 수 있지만 원본을 고치지는 못합니다.
- 원본 변경, 동의 철회와 만료 상태를 추적할 수 있어야 합니다.

## 4. 같은 팀의 다음 시즌 전환

### 4.1 이어지는 정보

| 정보 | 처리 |
| --- | --- |
| 선수 식별자 | 그대로 유지 |
| 이름·생년월일 | 유지하되 정정 이력 보존 |
| 주발·기본 포지션 | 이전 값을 제안하고 팀 매니저가 확인 |
| 팀 입단 이력 | 같은 팀에 계속 있으면 유지 |
| 연락처·비상 연락처 | 이전 값을 보여주되 시즌 시작 전 `확인 필요` |
| 지난 시즌 기록 | 새 시즌에서 비교 조회만 가능, 복제하지 않음 |
| 외부 장비 선수 연결 | 장비 연결 상태를 확인한 뒤 유지 |

### 4.2 새로 정하는 정보

| 정보 | 처리 |
| --- | --- |
| 공식 스쿼드 | 새 시즌 값 필수 |
| 학년 | 새 시즌 값 필수 |
| 등번호 | 이전 번호를 참고값으로만 표시, 새로 확정 |
| 주 포지션 | 새 시즌 시작 전 확인 |
| 학교 | 재학 학교와 확인일 갱신 |
| 시즌 등록 상태 | 새 시즌 값 생성 |
| 참가 제한 | 현재 유효한 제한만 담당 권한자가 검토 후 연결 |

### 4.3 이어지지 않는 정보

- 지난 시즌 일정과 참가자 목록
- 지난 시즌 운영 그룹
- 지난 시즌 등번호의 자동 확정
- 지난 시즌 컨디션과 일일 설문
- 만료된 참가 제한
- 지도자의 시즌 평가를 새 시즌 현재 평가로 복사한 값

### 4.4 전환 완료 조건

- 모든 선수의 `다음 시즌`, `졸업`, `이적·퇴단`, `결정 보류` 상태가 정해져 있습니다.
- 다음 시즌 선수는 스쿼드, 학년, 주 포지션과 학교가 확인되어 있습니다.
- 등번호와 주 소속 기간 충돌이 없습니다.
- 연락처·비상 연락처는 `확인됨` 또는 `확인 필요`가 명확합니다.
- 졸업·이적 선수의 종료일과 사유가 입력되어 있습니다.
- 보류 선수는 명단 활성화 대상에서 제외됩니다.

## 5. 졸업 선수 처리

### 5.1 상태 변경

1. 마지막 시즌 등록을 시즌 종료일에 종료합니다.
2. 팀 등록을 `졸업` 사유로 종료합니다.
3. 선수 상태를 `졸업생`으로 전환합니다.
4. 종료일 이후 일정과 새 알림 대상에서 제외합니다.
5. 과거 명단, 참가, 측정과 평가 기록은 해당 시즌 화면에 유지합니다.

### 5.2 접근 권한

- 일반 코치와 담당 스태프의 현재 연락처·의료 정보 접근은 졸업 적용일에 종료합니다.
- 구단 관리자는 정정, 인계와 권리 요청 처리에 필요한 범위에서만 접근합니다.
- 졸업생 목록은 현재 선수단과 분리하고 기본 검색 결과에서 제외합니다.
- 졸업생을 다시 등록하면 새 선수를 만들지 않고 기존 선수 식별자에 새 팀·시즌 등록을 연결합니다.

### 5.3 화면 표시

- `졸업생 · 2026 시즌 종료`처럼 상태와 마지막 시즌을 함께 표시합니다.
- 마지막 스쿼드, 등번호와 학교는 과거 시점 값으로 표시합니다.
- 현재 정보처럼 보이지 않도록 `2026.12.31 기준`을 함께 표시합니다.
- `선수 삭제` 대신 `보관`, `인계 준비`, `정보 정정 요청`을 제공합니다.

## 6. 다른 학교·구단으로 진학하거나 이적하는 경우

### 6.1 자동 공유 금지

다음 행동만으로는 이전 기록을 공개하지 않습니다.

- 새 학교가 이름과 생년월일을 입력함
- 출신 학교 이름을 선택함
- 이전 지도자가 구두로 확인함
- 같은 이메일·전화번호가 발견됨
- 중복 후보가 시스템에 표시됨

새 학교는 유효한 `데이터 인계 건`을 통해서만 이전 학교 확인본을 볼 수 있습니다.

### 6.2 내부 이동과 외부 이동 구분

- 같은 `구단·기관 ID` 안의 팀 이동은 내부 이동으로 처리합니다.
- 학교 이름이 같더라도 구단·기관 ID가 다르면 외부 이동입니다.
- 법인이 같다는 이유만으로 자동 통합하지 않습니다. 구단 관리자가 같은 개인정보처리 범위임을 확인한 기관만 내부 이동으로 설정합니다.

### 6.3 인계 상태

```text
작성 중 → 동의 대기 → 출신팀 확인 → 수신팀 검토 → 연결 완료
                 └→ 거절
                 └→ 만료
연결 완료 → 철회·종료
```

| 상태 | 의미 |
| --- | --- |
| 작성 중 | 출신팀이 목적·수신팀·제공 항목 작성 |
| 동의 대기 | 선수 또는 법정대리인의 범위별 동의 필요 |
| 출신팀 확인 | 출신팀 관리자가 데이터와 수신팀 확인 |
| 수신팀 검토 | 새 학교 관리자가 범위와 출처 확인 |
| 연결 완료 | 허용 범위의 읽기 전용 확인본 열람 가능 |
| 거절 | 동의 또는 출신·수신팀 확인 거절 |
| 만료 | 기한 안에 완료되지 않아 링크와 코드 무효 |
| 철회·종료 | 동의 철회, 목적 달성 또는 권한 종료로 접근 중단 |

## 7. 인계할 수 있는 데이터 범위

동의는 묶어서 한 번에 받지 않고 범위별로 분리합니다.

### 7.1 기본 인계

선수 등록과 동일인 연결에 필요한 최소 범위입니다.

- 이름
- 생년월일
- 선수 사진(선택)
- 주발과 기본 포지션
- 출신 구단·팀과 활동 기간
- 마지막 시즌·스쿼드·등번호
- 정보 확인일

### 7.2 경기·훈련 이력 요약

별도 선택 동의가 있을 때 제공합니다.

- 시즌별 참가 횟수 요약
- 포지션 이력
- 측정 항목별 최근값과 측정일
- GPS·체력 데이터의 기간 요약
- 출신팀이 공개 가능으로 확정한 객관 기록

원시 GPS 파일, 전체 세션 로그와 다른 선수의 비교값은 기본적으로 제공하지 않습니다.

### 7.3 연락 정보

새 학교가 별도로 수집하는 것을 기본으로 합니다. 인계가 필요한 경우 선수 연락처와 비상 연락처를 분리해 선택 동의를 받습니다.

### 7.4 의료·민감 정보

- 기본 인계에서 제외합니다.
- 진단명, 치료 기록, 상세 부상 메모와 참가 제한 사유는 별도 민감정보 동의와 수신 권한이 확인된 경우에만 제공합니다.
- 새 학교에는 필요한 참가 제한 결과와 유효기간만 제공하는 것을 우선합니다.
- 일반 코치·팀 매니저에게 의료 상세를 공개하지 않습니다.

### 7.5 제공하지 않는 정보

- 비공개 지도자 평가와 개인적 의견
- 징계 검토·상담 메모
- 팀 전술과 내부 운영 문서
- 다른 선수의 정보와 비교 순위
- 보호자와의 내부 커뮤니케이션 기록
- 동의 범위를 벗어난 원시 파일
- 삭제 또는 정정 요청이 처리 중인 값

## 8. 진학·이적 인계 절차

1. 출신팀 관리자가 선수의 `진학·이적 인계`를 시작합니다.
2. 수신 학교·구단을 BASE11 기관 목록에서 정확히 지정합니다.
3. 제공 목적, 데이터 항목과 열람 기간을 선택합니다.
4. 선수 또는 법정대리인에게 제공받는 기관, 목적, 항목, 보유·이용 기간과 거부 시 영향을 알립니다.
5. 범위별 동의를 기록합니다.
6. 출신팀 관리자가 확인본의 값과 확인일을 최종 검토합니다.
7. 일회용 인계 코드 또는 만료 링크를 발급합니다.
8. 수신팀 관리자가 기관 계정으로 로그인해 인계 건을 수락합니다.
9. BASE11이 기존 선수 식별자와 수신팀의 등록 대기를 연결합니다.
10. 수신팀은 확인본을 읽고 자체 현재 프로필·시즌 등록을 생성합니다.
11. 열람, 반영, 다운로드, 철회와 만료를 변경 기록에 남깁니다.

선수·학부모 앱이 없어도 1차 구현은 가능합니다. 팀 매니저가 인계를 시작하고, 동의는 본인 확인이 가능한 웹 동의 링크 또는 서면 동의 확인 기록으로 받습니다.

## 9. 새 학교에서 확인하는 방법

### 9.1 화면 구분

새 학교 선수 상세에는 다음을 섞지 않고 구분합니다.

- `출신팀 확인 정보`: 읽기 전용, 출처와 확인일 표시
- `현재 학교 정보`: 수신팀이 생성·수정
- `과거 시즌 요약`: 동의 범위 안에서 읽기 전용
- `공유되지 않은 정보`: 존재 여부도 노출하지 않음

### 9.2 값 반영

- 출신팀 확인값을 현재 학교 프로필에 반영할 때 새 값 버전을 만듭니다.
- 출신팀 확인본과 수신팀 현재값이 달라도 양쪽을 덮어쓰지 않습니다.
- 현재 학교가 수정한 값에는 `수신팀 확인` 출처를 표시합니다.
- 이전 정보가 잘못되었다면 수신팀이 직접 고치지 않고 출신팀에 정정 요청을 보냅니다.

### 9.3 확인 상태

| 표시 | 의미 |
| --- | --- |
| 출신팀 확인 | 출신팀 권한자가 확인한 값 |
| 본인 제출 | 선수 또는 법정대리인이 제출했으나 출신팀이 확인하지 않은 값 |
| 수신팀 확인 | 새 학교가 자체 확인한 값 |
| 확인 필요 | 오래되었거나 출처 확인이 끝나지 않은 값 |
| 철회됨 | 더 이상 열람할 수 없는 공유값 |

## 10. 동의와 아동 개인정보

제품 정책은 다음을 기본으로 합니다.

- 만 14세 미만 선수는 법정대리인의 동의와 동의 확인이 완료되어야 인계할 수 있습니다.
- 만 14세 이상은 선수 본인의 동의를 기본으로 하며, 구단 운영 규정상 필요한 보호자 확인은 별도로 받을 수 있습니다.
- 제3자 제공 동의 화면에는 제공받는 기관, 이용 목적, 제공 항목과 보유·이용 기간을 각각 표시합니다.
- 기본 정보, 경기·훈련 요약, 연락처와 의료 정보의 동의를 분리합니다.
- 선택 정보 제공에 동의하지 않아도 기본 선수 등록은 가능해야 합니다.
- 동의 시각, 동의 문구 버전, 확인 방법, 동의자와 법정대리인 확인 결과를 저장합니다.
- 동의 철회 방법은 동의 방법보다 어렵게 만들지 않습니다.

관련 법 기준은 개인정보 보호법의 [제17조 개인정보의 제공](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1027192575), [제22조의2 아동의 개인정보 보호](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=02&joNo=0022&lsiSeq=270351&urlMode=lsScJoRltInfoR), [제35조~제38조 정보주체 권리](https://law.go.kr/LSW/lsInfoP.do?lsiSeq=270351)를 검토 기준으로 사용합니다. 실제 출시 전 동의 문구, 개인정보처리자·처리위탁 관계와 보유기간은 별도 법률 검토를 완료해야 합니다.

## 11. 데이터 보관·파기 정책

### 11.1 공통 규칙

1. 모든 개인정보 종류에 `처리 목적`, `보관 근거`, `보관 종료일`을 저장합니다.
2. `무기한`을 기본값으로 허용하지 않습니다.
3. 졸업·퇴단 시 일반 운영 권한을 즉시 종료하고 보관 권한과 분리합니다.
4. 보관 목적이 끝난 정보는 삭제하거나 복구할 수 없게 파기합니다.
5. 다른 법령이나 분쟁 처리 때문에 남겨야 하는 정보는 운영 데이터와 분리 보관합니다.
6. 식별자가 필요 없는 통계는 익명화한 뒤 별도 집계 데이터로 보관합니다.
7. 개인정보 삭제가 과거 경기 결과 등 다른 사람의 기록을 훼손하는 경우 직접 식별자를 분리·가명화하고 관계 기록은 유지합니다.

개인정보 보호법 제21조는 보유기간 경과나 목적 달성으로 불필요해진 개인정보의 파기와, 별도 법적 보존이 필요한 정보의 분리 보관을 요구합니다. 안전조치와 접속기록 관리는 [제29조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029332029)를 검토 기준으로 사용합니다.

### 11.2 데이터별 처리

| 데이터 | 졸업·퇴단 직후 | 보관 종료 시 |
| --- | --- | --- |
| 현재 연락처·비상 연락처 | 일반 코치 접근 종료 | 삭제 또는 법적 보존 영역으로 분리 |
| 시즌 명단·등번호·참가 이력 | 종료 시즌에서 읽기 전용 | 직접 식별 필요성을 재검토하고 삭제·가명화 |
| 측정·GPS 원시 데이터 | 새 수집 중단, 인계 대상에서 기본 제외 | 목적이 끝나면 삭제, 통계는 익명화 |
| 지도자 메모 | 출신팀 내부 제한 | 목적 종료 시 삭제, 외부 인계 금지 |
| 의료 정보 | 메디컬·관리자 제한 | 별도 민감정보 기준에 따라 우선 파기 |
| 인계 확인본 | 동의한 수신팀만 기간 제한 열람 | 접근 종료 후 삭제 또는 분리 보관 |
| 동의·접근·정정 기록 | 운영 데이터와 분리 | 법률 검토로 확정한 기간 만료 후 파기 |

정확한 기간은 서비스가 임의로 고정하지 않습니다. 기관 유형, 계약과 법적 근거별 기간표를 확정한 뒤 `보관 정책 버전`으로 적용합니다. 기간표가 승인되지 않은 상태에서는 외부 학교 인계 기능을 출시하지 않습니다.

### 11.3 정보주체 권리 요청

- 열람
- 정정
- 삭제
- 처리정지
- 동의 철회
- 제공 현황 확인

요청자는 본인 또는 정당한 대리인인지 확인해야 합니다. 만 14세 미만 아동은 법정대리인이 요청할 수 있습니다. 요청 접수, 검토, 처리 결과와 이의 제기 경로를 기록합니다.

## 13. 예외 처리

| 상황 | 처리 |
| --- | --- |
| 출신팀이 BASE11을 사용하지 않음 | 본인 제출로 등록하며 출신팀 확인 표시 금지 |
| 수신팀이 BASE11을 사용하지 않음 | 선수·법정대리인에게 기간 제한 다운로드 제공, 이메일 자동 첨부 금지 |
| 출신팀이 폐쇄됨 | 기존 확인 권한자가 없으면 `출처 미확인` 처리, BASE11이 대신 확인하지 않음 |
| 수신 학교가 바뀜 | 기존 인계 코드와 권한 취소 후 새 기관 대상으로 동의 다시 받기 |
| 여러 학교에 동시에 인계 | 기관마다 별도 인계 건과 별도 동의 필요 |
| 인계 중 선수 정보가 정정됨 | 확인본 버전 갱신 후 변경 범위 재확인, 필요한 경우 재동의 |
| 동의가 철회됨 | 신규 열람 즉시 중단, 수신팀에 삭제·처리정지 작업 생성 |
| 인계 링크가 만료됨 | 접근 차단, 출신팀 확인 후 새 링크 발급 |
| 동일 선수 연결이 불확실함 | 수신팀 등록 대기로 유지, 자동 병합 금지 |
| 과거 기록에 다른 선수 정보가 섞임 | 해당 항목 인계 제외, 정정 완료 후 다시 생성 |
| 선수의 이전 학교 복귀 | 기존 선수 식별자에 새 팀·시즌 등록 생성, 과거 등록 재활성화 금지 |

## 15. 화면 요구사항

### 다음 시즌 명단

- 선수별 처리 상태
- 이전 값과 새 시즌 입력값 분리
- `이어짐`, `다시 확인`, `이어지지 않음` 표시
- 연락처·학교 확인 상태
- 졸업·이적 인계 시작

### 졸업생 관리

- 마지막 시즌·스쿼드·등번호
- 종료일과 졸업 사유
- 과거 기록 보기
- 인계 준비
- 정보 정정·권리 요청 상태

### 진학·이적 인계

- 수신 기관 정확한 선택
- 제공 목적과 범위
- 범위별 동의 상태
- 출신팀 확인본 미리보기
- 만료일과 철회
- 수신팀 열람·반영 기록

### 수신팀 검토

- 출신팀 확인값과 현재 입력값 비교
- 제공되지 않은 항목 숨김
- 출처·확인일·유효기간
- 현재 프로필 반영 또는 별도 유지
- 정정 요청

## 16. 출시 차단 조건

다음 항목이 하나라도 없으면 외부 학교 데이터 인계 기능을 출시하지 않습니다.

- [ ] 제공 기관, 목적, 항목, 보유·이용 기간을 구분해 동의받는다.
- [ ] 만 14세 미만 법정대리인 동의와 확인 절차가 있다.
- [ ] 기본, 경기·훈련, 연락처와 의료 정보의 동의가 분리되어 있다.
- [ ] 출신팀 원본과 수신팀 현재값이 분리된다.
- [ ] 모든 값에 출처와 확인일이 표시된다.
- [ ] 동의 철회와 인계 만료 시 접근이 중단된다.
- [ ] 수신팀의 열람·다운로드·반영 기록이 남는다.
- [ ] 데이터 종류별 보관 종료일과 파기 작업이 있다.
- [ ] 정보주체의 열람·정정·삭제·처리정지 요청 절차가 있다.
