## 1. 제품 정의

### 1.1 한 문장

BASE11은 한국 유소년 축구팀의 **선수단, 시즌, 일정, 훈련·경기 기록과 스태프 업무를 관리하는 지도자용 소프트웨어**입니다.

### 1.2 제품 메시지

초기 제품에서는 별도 슬로건을 사용하지 않고 제품이 하는 일을 직접 설명합니다.

### 1.3 제품이 제공해야 하는 결과

1. 팀 매니저는 선수와 스태프를 중복 없이 등록하고 시즌별 명단을 관리합니다.
2. 코치는 오늘 무엇을 확인하고 결정해야 하는지 빠르게 파악합니다.
3. 감독과 스태프는 같은 훈련 계획을 검토하고 변경 이력을 공유합니다.
4. 훈련·경기 후 GPS, 컨디션, 부상과 코치 메모가 같은 세션에 모입니다.
5. U16·U17·U18이 분리·통합되는 팀도 한 선수의 기록을 이어서 관리합니다.
6. 지도자는 검증된 훈련 세션을 공유·판매하고 구매한 자료를 자신의 일정에 바로 적용합니다.
7. 팀 매니저와 감독은 시즌 예산, 수입·지출, 증빙과 승인 이력을 같은 시스템에서 관리합니다.

## 2. 해결하려는 문제

### 2.1 엘리트 유소년 지도자의 실제 루틴

지도자의 하루와 한 주는 다음 흐름을 반복합니다.

1. 다음 경기를 기준으로 주간 훈련 목표와 강도를 계획합니다.
2. 선수의 컨디션, 부상·제한과 최근 부하를 확인합니다.
3. 스태프별 훈련 블록과 담당 역할을 조율합니다.
4. 선수단 또는 일부 스쿼드에 일정과 준비 사항을 전달합니다.
5. 현장에서 선수 구성과 훈련 강도를 조정합니다.
6. 세션 후 GPS·RPE·메모와 선수별 관찰 내용을 정리합니다.
7. 개선이 필요한 선수에게 훈련 과제와 코칭 포인트를 전달합니다.
8. 결과를 다음 훈련과 경기 계획에 반영합니다.

### 2.2 주요 애로사항

| 문제 | 현장의 모습 | 제품이 제공할 해결 방식 |
| --- | --- | --- |
| 정보가 여러 도구에 흩어짐 | 일정, 메신저, 엑셀, GPS 파일과 코치 노트가 분리됨 | `TrainingSession`을 중심으로 연결 |
| 정상 데이터까지 모두 확인해야 함 | 중요한 선수와 누락 데이터가 묻힘 | 정상은 줄이고 예외·결정 항목 우선 노출 |
| 반복 입력 부담 | 매 세션마다 같은 피드백과 명단을 다시 작성 | 이전 기록, 템플릿과 대상 규칙 재사용 |
| 계획과 실행이 이어지지 않음 | 훈련 계획, 실제 참가, GPS와 회고가 별도 기록 | 계획 대상과 실제 참가자를 구분해 한 흐름으로 저장 |
| 선수 피드백이 추상적임 | “더 집중하자” 수준으로 끝나기 쉬움 | 관찰 내용 → 코치 과제 → 확인 기준 → 재점검 |
| 연령별 운영이 복잡함 | U16·U17·U18이 합동·분리되고 월반 선수가 발생 | 공식 소속과 운영 단위를 분리 |
| 역할별 소통 범위가 다름 | 선수, 학부모, 지도자에게 같은 내용을 보낼 수 없음 | 역할·스쿼드·그룹별 공개본과 공지 대상 관리 |

## 3. 핵심 사용자

### 3.1 감독·헤드코치

- 팀 전체 계획과 주간 강도를 결정합니다.
- 스태프 제안을 승인·유지·거절합니다.
- 선수 이슈와 피드백 우선순위를 정합니다.
- 선수·학부모 공개 범위를 최종 관리합니다.

### 3.2 스쿼드 코치·포지션 코치

- 담당 스쿼드 또는 배정 세션을 준비합니다.
- 훈련 블록과 선수별 관찰 내용을 기록합니다.
- 선수별 관찰 내용과 다음 점검 항목을 기록합니다.

### 3.3 팀 매니저

- 팀, 시즌, 스쿼드와 선수 명단을 관리합니다.
- 선수 입단, 소속 이동, 등번호 변경과 퇴단 이력을 정리합니다.
- 스태프 초대, 일정 대상과 정보 누락을 확인합니다.

### 3.4 피지컬 코치

- GPS·RPE 데이터 품질과 선수별 부하를 관리합니다.
- 세션 강도와 회복 상태에 대한 판단 근거를 제공합니다.

### 3.5 메디컬 스태프

- 부상·통증·참여 제한과 복귀 상태를 관리합니다.
- 코치가 알아야 할 참여 제한과 비공개 의료 상세를 구분합니다.

### 3.6 선수

- 오늘 일정, 준비 사항과 개인 미션을 확인합니다.
- 본인에게 공개된 피드백, 성장·피지컬 기록과 팀 정보를 봅니다.
- 긴 문서보다 지금 신경 써야 할 행동을 이해해야 합니다.

### 3.7 학부모

- 자녀와 관련된 일정, 이동 안내와 공식 공지를 확인합니다.
- 공개가 허용된 자녀 상태와 코치 피드백만 봅니다.
- 코치 내부 판단이나 의료 상세에는 접근하지 않습니다.

## 4. 제품 원칙

1. **세션 중심**
   일정, 훈련 블록, 참가자, GPS, 컨디션, 부상, 메모와 피드백은 같은 세션을 참조합니다.

2. **결정이 필요한 것부터**
   정상 상태 전체를 나열하기보다 예외, 누락과 승인 대기를 먼저 보여줍니다.

3. **출석보다 실제 참가자**
   엘리트 선수단에 독립적인 출석 관리 기능을 두지 않습니다. 세션의 실제 참가자와 참가 방식을 기록합니다.

4. **수면은 필수 기록에서 제외**
   선수 상태는 컨디션, 부상·제한, 최근 부하와 현장 판단을 중심으로 관리합니다.

5. **코치가 작성한 기록을 기준으로 사용**
   선수 과제와 피드백은 코치가 작성하고 수정한 내용을 기준으로 저장합니다.

6. **공식 소속과 운영 단위 분리**
   선수의 주 소속 스쿼드는 안정적으로 유지하고 실제 훈련·경기 대상은 유연하게 구성합니다.

7. **역할별 공개본 분리**
   스태프 내부 정보, 선수 공개 정보와 학부모 공개 정보를 데이터 단계부터 분리합니다.

8. **변경 이력 보존**
   세션 계획, 소속, 참여 제한, 피드백과 공개 범위의 주요 변경을 추적합니다.

## 5. 핵심 제품 흐름

### 5.0 팀·선수 설정 흐름

```text
계속 유지할 팀 생성
  → 시즌 기간 설정
  → 공식 스쿼드 생성
  → 팀 매니저와 스태프 배정
  → 선수 개별·일괄 등록
  → 중복·누락 확인
  → 시즌 명단 활성화
```

선수 등록과 시즌 전환의 상세 규칙은 [팀·선수 등록 및 관리 정책](./TEAM_PLAYER_MANAGEMENT_POLICY.md)을 따릅니다.

### 5.1 팀 운영 루프

```text
경기 기준 계획
  → 스태프 협업·검토
  → 역할별 게시
  → 현장 실행·참가자 확정
  → GPS·컨디션·부상·메모 연결
  → 선수별 개선 과제와 피드백
  → 다음 계획에 반영
```

각 단계는 별도의 문서가 아니라 같은 경기, 마이크로사이클과 세션 ID를 기준으로 이어집니다.

### 5.2 일정 생성 흐름

```text
일정 유형
  → 대상 스쿼드·운영 그룹·개인 구성
  → 시간·장소
  → 훈련 내용과 담당자
  → 선수·학부모·지도자 공개 범위
  → 게시
```

- 대상은 복수 스쿼드, 운영 그룹, 개인 추가와 제외를 조합합니다.
- 일정에는 예상 대상을 저장하고 실제 참가자는 세션에서 확정합니다.
- 같은 통합 세션을 U16·U17·U18별로 중복 생성하지 않습니다.

### 5.3 세션 운영 흐름

```text
계획 대상 확인
  → 실제 참가자 확정
  → 컨디션·부상·제한 확인
  → 훈련 블록 실행
  → GPS·RPE 연결
  → 코치 메모
  → 바로 피드백 또는 개선 과제 연결
```

### 5.4 개선 과제·피드백 흐름

```text
코치 관찰 내용 기록
  → 선수 과제와 확인 기준 작성
  → 담당 코치 확인
  → 선수에게 미션으로 전달
  → 개인 실행 기록
  → 다음 세션 현장 점검
  → 완료·유지·재처방
```

피드백의 기본 구조는 다음과 같습니다.

- 무엇이 부족했는가
- 어떤 상황에서 나타났는가
- 어떤 훈련을 해야 하는가
- 훈련 중 무엇을 신경 써야 하는가
- 성공 여부를 어떻게 확인하는가
- 언제 다시 점검하는가

### 5.5 공지 흐름

```text
공지 내용 작성
  → 역할 선택
  → 팀·스쿼드·운영 그룹 선택
  → 개인 추가·제외
  → 예상 수신자와 개인정보 범위 검토
  → 즉시 또는 예약 발송
  → 확인율·미확인자 관리
```

| 핵심 | 오늘 | 지금 결정·처리할 일 확인 | 선수 예외, 오늘 일정, 승인·누락 |
| 핵심 | 선수단 | 선수 등록과 전체 기록 관리 | 상태, 훈련·경기, 성장, 부상, 상담, 소속 |
| 핵심 | 일정 | 훈련·경기 등록과 현장 운영 | 계획, 참가자, 엔트리, 기록, 완료 |
| 보조 | 운영센터 | 지도자 사업·팀 운영 관리 | 세션 마켓, 내 판매, 팀 재무, 정산 |
| 보조 | 팀 설정 | 팀·시즌·스태프·권한 관리 | 팀 정보, 시즌 전환, 권한, 보관 |

공지, 피드백, 경기 기록과 스쿼드 상태는 별도 주 메뉴로 노출하지 않고 `오늘`, `선수단`, `일정`의 관련 맥락에서 제공합니다.

공통 화면 요소:

- 팀·시즌 선택
- 전역 스쿼드·운영 그룹 범위
- 선수·세션·목표·데이터 통합 검색
- 변경 저장 상태와 알림

## 8. 핵심 데이터 개념

```text
Organization
  └─ Team
      ├─ Staff Assignment
      ├─ Team Player Registration ── Player
      └─ Season
          ├─ Official Squad
          ├─ Season Roster Entry ── Player
          │   └─ Squad Assignment
          ├─ Operating Group
          ├─ Match
          │   └─ Microcycle
          │       └─ Training Session
          │           ├─ Session Scope
          │           ├─ Session Participant
          │           ├─ Training Block
          │           ├─ Performance Metric
          │           ├─ Player Issue
          │           ├─ Staff Review
          │           ├─ Feedback / Player Goal
          │           └─ Publication
          └─ Notice / Audience
```

핵심 저장 기준:

- 일정 대상: `Session Scope`
- 실제 참가: `Session Participant`
- 선수별 세션 데이터: `Player × Session`
- 팀 소속: 적용 기간이 있는 `Team Player Registration`
- 시즌 명단: `Season Roster Entry`
- 공식 스쿼드: 적용 기간이 있는 `Squad Assignment`
- 실제 운영 단위: 복수 가입 가능한 `Operating Group`
- 역할별 공개 정보: `Publication`

세부 규칙은 [선수단 운영 정책](./SQUAD_OPERATIONS_POLICY.md)을 따릅니다.
선수 원본, 팀 등록, 시즌 등록과 등번호 이력은 [팀·선수 등록 및 관리 정책](./TEAM_PLAYER_MANAGEMENT_POLICY.md)을 따릅니다.

## 11. 범위와 비범위

1차 제품 사용자는 한국 엘리트 유소년 축구팀의 감독, 코치, 팀 매니저와 전문 스태프입니다. 현재 디자인과 개발 우선순위는 Coach Desktop과 Coach Mobile에 둡니다. 선수·학부모 전용 경험은 공개 범위와 수신자 정책만 안전하게 유지하고, 코치 핵심 운영 흐름이 완성된 뒤 고도화합니다.

- 엘리트 유소년 팀의 코치 운영
- 팀, 시즌, 공식 스쿼드와 선수 등록
- 팀 매니저의 명단·소속 이력 관리
- 경기 기준 마이크로사이클
- 훈련·경기 세션
- 선수 컨디션·부상·참여 판단
- GPS·RPE 연결
- 선수 성장·피지컬 기록
- 코치가 작성하는 선수 과제와 피드백
- 역할별 공지와 공개
- U16·U17·U18 통합·분리·혼합 운영

### 11.2 현재 독립 기능으로 두지 않는 항목

- 일반 학교·생활체육형 출석부
- 수면 필수 설문과 수면 점수
- 학부모용 의료 상세
- 자동 훈련 처방과 자동 추천 문구

- 구단·팀·시즌·스쿼드·선수의 용어와 상태 통일

## 15. 제품 완료 기준

- [ ] 코치는 선택한 팀·스쿼드 범위에서 오늘의 결정 항목을 확인할 수 있다.
- [ ] 팀 매니저는 선수 계정 없이 선수를 등록할 수 있다.
- [ ] 한 선수를 복제하지 않고 다음 시즌과 다른 스쿼드에 연결할 수 있다.
- [ ] 소속, 학년, 포지션과 등번호 변경 이력을 확인할 수 있다.
- [ ] 월·주 캘린더에서 일정 유형과 대상 스쿼드를 구분할 수 있다.
- [ ] 한 일정에 여러 스쿼드·그룹·개인을 조합할 수 있다.
- [ ] 계획 대상과 실제 참가자가 분리되어 저장된다.
- [ ] 세션에서 선수별 컨디션·부상·GPS·RPE·피드백을 확인할 수 있다.
- [ ] 선수 상세에서 현재 소속, 소속 이력, 성장·피지컬 기록을 볼 수 있다.
- [ ] 코치가 작성한 선수 과제만 선수에게 전달된다.
- [ ] 선수·학부모·지도자별 공개 정보가 분리된다.
- [ ] 공지 발송 전에 예상 수신자와 제외 대상을 확인할 수 있다.
- [ ] 모든 주요 변경에 사용자와 시각이 기록된다.
- [ ] 정상·빈 상태·오류·권한 없음·동기화 지연 상태가 정의된다.

## 16. 남은 제품 결정

1. 실제 참가자 확정 시점을 세션 시작 전, 종료 후 또는 양쪽 모두로 둘지
2. 선수 컨디션 입력의 주체를 선수, 코치 또는 혼합으로 둘지
3. 학부모에게 공개할 성장·피지컬 지표의 기본 범위
4. 영상 장면을 세션·선수·피드백 중 어디에 우선 연결할지
5. 코치 모바일의 세션 운영 기능을 데스크톱과 어느 수준까지 동일하게 제공할지
