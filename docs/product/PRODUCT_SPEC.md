제품이나 화면 방향을 변경할 때 이 문서를 먼저 수정하고, 세부 규칙이 바뀌는 경우 연결된 정책서도 함께 수정합니다.

## 1. 제품 정의

### 1.1 한 문장

BASE11은 엘리트 유소년 축구팀의 **계획, 현장 실행, 선수 데이터, 코칭 피드백과 역할별 소통을 하나의 세션 흐름으로 연결하는 코칭 운영체제**입니다.

### 1.2 제품 메시지

> 선수의 다음을 만드는 팀의 베이스

### 1.3 제품이 제공해야 하는 결과

1. 코치는 오늘 무엇을 결정해야 하는지 빠르게 파악합니다.
2. 감독과 스태프는 같은 훈련 계획을 검토하고 변경 이력을 공유합니다.
3. 훈련·경기 후 GPS, 컨디션, 부상과 코치 메모가 같은 세션에 모입니다.
4. 선수가 부족했던 항목은 적절한 훈련과 코칭 포인트로 연결됩니다.
5. 선수와 학부모는 각자에게 공개된 정보만 이해하기 쉬운 형태로 받습니다.
6. U16·U17·U18이 분리·통합되는 팀도 선수를 중복 등록하지 않고 운영합니다.

## 2. 해결하려는 문제

### 2.1 엘리트 유소년 지도자의 실제 루틴

지도자의 하루와 한 주는 다음 흐름을 반복합니다.

1. 다음 경기를 기준으로 주간 훈련 목표와 강도를 계획합니다.
2. 선수의 컨디션, 부상·제한과 최근 부하를 확인합니다.
3. 스태프별 훈련 블록과 담당 역할을 조율합니다.
4. 선수단 또는 일부 스쿼드에 일정과 준비 사항을 전달합니다.
5. 현장에서 선수 구성과 훈련 강도를 조정합니다.
6. 세션 후 GPS·RPE·메모와 선수별 관찰 내용을 정리합니다.
7. 개선이 필요한 선수에게 훈련 과제와 코칭 포인트를 전달합니다.
8. 결과를 다음 훈련과 경기 계획에 반영합니다.

### 2.2 주요 애로사항

| 문제 | 현장의 모습 | 제품이 제공할 해결 방식 |
| --- | --- | --- |
| 정보가 여러 도구에 흩어짐 | 일정, 메신저, 엑셀, GPS 파일과 코치 노트가 분리됨 | `TrainingSession`을 중심으로 연결 |
| 정상 데이터까지 모두 확인해야 함 | 중요한 선수와 누락 데이터가 묻힘 | 정상은 줄이고 예외·결정 항목 우선 노출 |
| 반복 입력 부담 | 매 세션마다 같은 피드백과 명단을 다시 작성 | 데이터 기반 추천, 템플릿과 대상 규칙 재사용 |
| 계획과 실행이 이어지지 않음 | 훈련 계획, 실제 참가, GPS와 회고가 별도 기록 | 계획 대상과 실제 참가자를 구분해 한 흐름으로 저장 |
| 선수 피드백이 추상적임 | “더 집중하자” 수준으로 끝나기 쉬움 | 부족 항목 → 추천 훈련 → 코칭 포인트 → 성공 기준 → 재점검 |
| 연령별 운영이 복잡함 | U16·U17·U18이 합동·분리되고 월반 선수가 발생 | 공식 소속과 운영 단위를 분리 |
| 역할별 소통 범위가 다름 | 선수, 학부모, 지도자에게 같은 내용을 보낼 수 없음 | 역할·스쿼드·그룹별 공개본과 공지 대상 관리 |

## 3. 핵심 사용자

### 3.1 감독·헤드코치

- 팀 전체 계획과 주간 강도를 결정합니다.
- 스태프 제안을 승인·유지·거절합니다.
- 선수 이슈와 피드백 우선순위를 정합니다.
- 선수·학부모 공개 범위를 최종 관리합니다.

### 3.2 스쿼드 코치·포지션 코치

- 담당 스쿼드 또는 배정 세션을 준비합니다.
- 훈련 블록과 선수별 관찰 내용을 기록합니다.
- 추천된 개선 과제를 검토하고 선수에게 전달합니다.

### 3.3 피지컬 코치

- GPS·RPE 데이터 품질과 선수별 부하를 관리합니다.
- 세션 강도와 회복 상태에 대한 판단 근거를 제공합니다.

### 3.4 메디컬 스태프

- 부상·통증·참여 제한과 복귀 상태를 관리합니다.
- 코치가 알아야 할 참여 제한과 비공개 의료 상세를 구분합니다.

### 3.5 선수

- 오늘 일정, 준비 사항과 개인 미션을 확인합니다.
- 본인에게 공개된 피드백, 성장·피지컬 기록과 팀 정보를 봅니다.
- 긴 문서보다 지금 신경 써야 할 행동을 이해해야 합니다.

### 3.6 학부모

- 자녀와 관련된 일정, 이동 안내와 공식 공지를 확인합니다.
- 공개가 허용된 자녀 상태와 코치 피드백만 봅니다.
- 코치 내부 판단이나 의료 상세에는 접근하지 않습니다.

## 4. 제품 원칙

1. **세션 중심**
   일정, 훈련 블록, 참가자, GPS, 컨디션, 부상, 메모와 피드백은 같은 세션을 참조합니다.

2. **결정이 필요한 것부터**
   정상 상태 전체를 나열하기보다 예외, 누락과 승인 대기를 먼저 보여줍니다.

3. **출석보다 실제 참가자**
   엘리트 선수단에 독립적인 출석 관리 기능을 두지 않습니다. 세션의 실제 참가자와 참가 방식을 기록합니다.

4. **수면은 필수 기록에서 제외**
   선수 상태는 컨디션, 부상·제한, 최근 부하와 현장 판단을 중심으로 관리합니다.

5. **코치 승인형 자동화**
   시스템은 개선 과제와 훈련을 추천하지만 선수에게 자동 전달하지 않습니다. 코치가 수정·승인합니다.

6. **공식 소속과 운영 단위 분리**
   선수의 주 소속 스쿼드는 안정적으로 유지하고 실제 훈련·경기 대상은 유연하게 구성합니다.

7. **역할별 공개본 분리**
   스태프 내부 정보, 선수 공개 정보와 학부모 공개 정보를 데이터 단계부터 분리합니다.

8. **변경 이력 보존**
   세션 계획, 소속, 참여 제한, 피드백과 공개 범위의 주요 변경을 추적합니다.

## 5. 핵심 제품 흐름

### 5.1 팀 운영 루프

```text
경기 기준 계획
  → 스태프 협업·검토
  → 역할별 게시
  → 현장 실행·참가자 확정
  → GPS·컨디션·부상·메모 연결
  → 선수별 개선 과제와 피드백
  → 다음 계획에 반영
```

각 단계는 별도의 문서가 아니라 같은 경기, 마이크로사이클과 세션 ID를 기준으로 이어집니다.

### 5.2 일정 생성 흐름

```text
일정 유형
  → 대상 스쿼드·운영 그룹·개인 구성
  → 시간·장소
  → 훈련 내용과 담당자
  → 선수·학부모·지도자 공개 범위
  → 게시
```

- 대상은 복수 스쿼드, 운영 그룹, 개인 추가와 제외를 조합합니다.
- 일정에는 예상 대상을 저장하고 실제 참가자는 세션에서 확정합니다.
- 같은 통합 세션을 U16·U17·U18별로 중복 생성하지 않습니다.

### 5.3 세션 운영 흐름

```text
계획 대상 확인
  → 실제 참가자 확정
  → 컨디션·부상·제한 확인
  → 훈련 블록 실행
  → GPS·RPE 연결
  → 코치 메모
  → 바로 피드백 또는 개선 과제 연결
```

### 5.4 개선 과제·피드백 흐름

```text
반복된 부족 신호 탐지
  → 추천 훈련과 코칭 포인트 생성
  → 근거와 신뢰도 표시
  → 코치 수정·승인
  → 선수에게 미션으로 전달
  → 개인 실행 기록
  → 다음 세션 현장 점검
  → 완료·유지·재처방
```

피드백의 기본 구조는 다음과 같습니다.

- 무엇이 부족했는가
- 어떤 상황에서 나타났는가
- 어떤 훈련을 해야 하는가
- 훈련 중 무엇을 신경 써야 하는가
- 성공 여부를 어떻게 확인하는가
- 언제 다시 점검하는가

### 5.5 공지 흐름

```text
공지 내용 작성
  → 역할 선택
  → 팀·스쿼드·운영 그룹 선택
  → 개인 추가·제외
  → 예상 수신자와 개인정보 범위 검토
  → 즉시 또는 예약 발송
  → 확인율·미확인자 관리
```

## 7. 기능 기획

### 7.1 마이크로사이클 대시보드

목표:

- 지도자가 1분 안에 오늘의 우선순위를 파악합니다.
- 다음 경기를 기준으로 계획, 실행과 데이터 상태를 연결합니다.

주요 정보:

- MD 기준 오늘 세션과 이번 주 강도
- 선수 이슈와 참여 제한
- 스태프 검토 대기
- GPS·RPE 연결 상태
- 다음 계획에 반영할 결정

### 7.2 일정과 캘린더

목표:

- 월·주 보기에서 전체 팀 또는 선택한 스쿼드의 일정을 비교합니다.
- 일정 유형과 대상 스쿼드를 시각적으로 혼동하지 않습니다.

주요 기능:

- 월·주 보기 전환
- 전체 선수단, U16, U17, U18, 운영 그룹 범위 선택
- 훈련·경기·회복·회의 유형 색상
- 스쿼드·운영 그룹 칩
- 반복, 복제, 변경과 취소
- 대상 변경 시 영향 인원과 공개 범위 확인

### 7.3 훈련·경기 상세

목표:

- 하루의 계획, 선수 상태, 실행 결과와 피드백을 한 화면에서 관리합니다.

공통 탭:

- 개요
- 선수
- GPS·RPE 또는 경기 부하
- 메모·피드백

훈련 상세:

- 훈련 목표와 블록
- 블록별 시간, 그룹, 담당자와 강도
- 계획 대상과 실제 참가자
- 컨디션, 부상·제한과 참여 판단
- GPS·RPE 데이터
- 코치 내부 메모와 선수 피드백

경기 상세:

- 상대, 대회, 포메이션과 엔트리
- 득점, 교체, 부상과 전술 변경 장면
- 출전 시간과 선수별 부하
- 감독 총평과 선수 피드백

### 7.4 선수단

목표:

- 현재 상태와 특이사항이 있는 선수를 먼저 발견합니다.

선수단 목록:

- 공식 스쿼드 기준 그룹
- 운영 그룹과 포지션 필터
- 오늘 컨디션
- 부상·참여 제한
- 최근 부하
- GPS와 피드백 상태

선수 상세:

- 현재 주 소속, 참가 가능 스쿼드와 운영 그룹
- 컨디션과 부상·제한
- 최근 훈련·경기와 GPS·RPE
- 신장, 체중과 성장 기록
- 스프린트, 점프, 지구력 등 개인 피지컬 기록
- 소속 이력과 교차 스쿼드 참가

### 7.5 스쿼드 상태

목표:

판단 정보:

- 선수 컨디션
- 통증과 부상·제한
- 최근 세션 부하
- 가용 시간과 제한 강도

### 7.6 미션·피드백

목표:

- 코치가 매번 문장을 처음부터 작성하지 않고도 구체적이고 실행 가능한 피드백을 전달합니다.

추천 개선 과제:

- 추천 대기, 전달 완료, 보류 상태
- 기술·전술·피지컬 카테고리
- 반복 신호, 경기 메모와 추천 신뢰도
- 추천 훈련
- 선수에게 전달할 코칭 포인트
- 성공 기준과 다음 점검일
- 선수·지도자·학부모 공개 범위
- 코치 수정, 승인과 전달

선수 개선 추적:

- 전달 이후 개인 훈련 실행
- 선수 질문과 코치 답변
- 다음 세션 현장 점검
- 과제 완료, 유지와 재처방 이력

### 7.7 GPS·퍼포먼스 데이터

목표:

주요 기능:

- 선수 중복·미매칭 검증

- 중요·예약 상태
- 연결 일정과 첨부

### 7.9 스태프 협업과 권한

## 8. 핵심 데이터 개념

```text
Organization
  └─ Team
      └─ Season
          ├─ Official Squad
          ├─ Player Membership
          ├─ Operating Group
          ├─ Match
          │   └─ Microcycle
          │       └─ Training Session
          │           ├─ Session Scope
          │           ├─ Session Participant
          │           ├─ Training Block
          │           ├─ Performance Metric
          │           ├─ Player Issue
          │           ├─ Staff Review
          │           ├─ Feedback / Player Goal
          │           └─ Publication
          └─ Notice / Audience
```

핵심 저장 기준:

- 일정 대상: `Session Scope`
- 실제 참가: `Session Participant`
- 선수별 세션 데이터: `Player × Session`
- 공식 소속: 적용 기간이 있는 `Player Membership`
- 실제 운영 단위: 복수 가입 가능한 `Operating Group`
- 역할별 공개 정보: `Publication`

세부 규칙은 [선수단 운영 정책](./SQUAD_OPERATIONS_POLICY.md)을 따릅니다.

- [ ] 세션에서 선수별 컨디션·부상·GPS·RPE·피드백을 확인할 수 있다.
- [ ] 선수 상세에서 현재 소속, 소속 이력, 성장·피지컬 기록을 볼 수 있다.
- [ ] 추천 개선 과제는 코치 승인 후에만 선수에게 전달된다.
- [ ] 선수·학부모·지도자별 공개 정보가 분리된다.
- [ ] 공지 발송 전에 예상 수신자와 제외 대상을 확인할 수 있다.
- [ ] 모든 주요 변경에 사용자와 시각이 기록된다.
- [ ] 정상·빈 상태·오류·권한 없음·동기화 지연 상태가 정의된다.

## 16. 남은 제품 결정

1. 팀 설정에서 운영 모드를 직접 선택하게 할지, 스쿼드 수와 사용 패턴으로 자동 단순화할지
2. 실제 참가자 확정 시점을 세션 시작 전, 종료 후 또는 양쪽 모두로 둘지
3. 선수 컨디션 입력의 주체를 선수, 코치 또는 혼합으로 둘지
4. 학부모에게 공개할 성장·피지컬 지표의 기본 범위
5. 추천 개선 과제 생성에 필요한 최소 반복 신호와 신뢰도 기준
6. 영상 장면을 세션·선수·피드백 중 어디에 우선 연결할지
7. 코치 모바일의 세션 운영 기능을 데스크톱과 어느 수준까지 동일하게 제공할지
