## 1. 목적

고등부 한 팀 안에서 U16, U17, U18이 분리 훈련을 하거나 통합 훈련을 하는 현실을 하나의 제품 구조로 지원합니다.

핵심은 선수의 **공식 소속**과 실제 훈련·경기에서의 **운영 단위**를 분리하는 것입니다. 선수는 한 번만 등록하고, 일정마다 참가 범위를 유연하게 구성하며, 실제 데이터는 참가한 선수 기준으로 저장합니다.

## 2. 제품 원칙

1. 선수 한 명은 한 시즌에 하나의 `주 소속 스쿼드`를 갖습니다.
2. 통합 훈련과 상위 연령 경기 참가 때문에 선수를 중복 등록하지 않습니다.
3. 일정에 지정한 대상은 계획이고, 세션에 저장된 참가자는 실제 기록의 기준입니다.
4. GPS, 컨디션, 부상, 피드백은 `선수 × 세션` 단위로 저장합니다.
5. 일정 색상은 훈련·경기·회복·회의 등 `일정 유형`을 나타냅니다.
6. U16·U17·U18과 운영 그룹은 별도의 칩이나 라벨로 표시합니다.
7. 승격, 월반, 임시 합류와 스쿼드 이동은 과거 기록을 덮어쓰지 않고 적용 기간을 남깁니다.
8. 단일 스쿼드만 운영하는 팀에는 불필요한 범위 선택 UI를 숨깁니다.

## 3. 용어

| 용어 | 의미 | 예시 |
| --- | --- | --- |
| 팀 | 여러 시즌 동안 유지되는 지도자 운영 단위 | FC 안양 고등부 |
| 시즌 | 소속과 기록의 기준 기간 | 2026 시즌 |
| 공식 스쿼드 | 연령·등록 기준의 주 소속 | U16, U17, U18 |
| 운영 그룹 | 실제 훈련 목적에 따라 만든 유동 그룹 | 1군 준비조, 재활조, GK 그룹 |
| 세션 범위 | 일정 생성 시 초대한 스쿼드·그룹·개인 | U17 + U18 일부 |
| 세션 참가자 | 실제로 훈련·경기에 참가한 선수 | 26명 |
| 경기 엔트리 | 특정 경기에 등록된 선수 명단 | 선발 11, 교체 9 |
| 공개 대상 | 공지나 세션 공개본을 볼 수 있는 역할·그룹 | U18 선수와 학부모 |

## 4. 운영 모드

데이터 구조는 모든 팀에서 동일하게 유지하고, 설정과 화면 노출만 단순화합니다.

### 4.1 통합 운영

- 팀 전체가 대부분 함께 훈련합니다.
- 기본 범위는 `전체 선수단`입니다.
- U16·U17·U18 필터는 필요할 때만 사용합니다.

### 4.2 연령별 분리 운영

- U16·U17·U18이 별도 일정과 코칭 스태프로 운영됩니다.
- 로그인 후 기본 범위는 지도자의 담당 스쿼드입니다.
- 팀 전체 데이터는 권한이 있을 때만 볼 수 있습니다.

### 4.3 혼합 운영

- 연령별 기본 소속은 유지하되 세션마다 함께 훈련하거나 일부 선수가 상위 스쿼드에 참가합니다.
- 제품의 권장 기본 모드입니다.
- 일정 생성 시 여러 스쿼드, 운영 그룹, 개인 선수를 조합할 수 있습니다.

## 5. 핵심 데이터 정책

### 5.1 선수 소속

- 한 선수는 한 시즌에 `primary_squad_id` 하나를 가집니다.
- 상위 스쿼드 참가 자격이나 관찰 대상은 별도 자격 정보로 관리합니다.
- 운영 그룹은 여러 개에 속할 수 있으며 시작일과 종료일을 가집니다.
- 시즌 중 공식 소속 이동은 기존 소속의 종료일과 새 소속의 시작일을 기록합니다.
- 선수 이름이나 생년월일이 같다는 이유로 자동 병합하지 않습니다. 내부 선수 ID가 기준입니다.

### 5.2 일정과 세션

- 일정은 다음 대상을 하나 이상 가질 수 있습니다.
  - 공식 스쿼드
  - 운영 그룹
  - 개별 선수 추가
  - 개별 선수 제외
- 초대 대상은 일정 편집 시 자동 계산되지만, 실제 참가자는 세션 시작 전후에 확정합니다.
- 일정 복제 시 대상 규칙은 복제하고 실제 참가자와 기록은 복제하지 않습니다.
- 캘린더 월·주 보기에서 같은 통합 세션을 스쿼드별로 중복 생성하지 않습니다.

### 5.3 선수 데이터

- 컨디션, 부상·제한, GPS, RPE, 코치 메모와 피드백은 `player_id + session_id`를 기준으로 저장합니다.
- 수면은 별도 필수 기록 항목으로 두지 않습니다.
- 세션 평균은 해당 세션의 실제 참가자만 포함합니다.
- 공식 소속별 통계는 기록 당시 소속 이력을 기준으로 계산합니다.
- 신체 정보와 성장 기록은 측정일을 포함한 시계열로 보존합니다.

### 5.4 경기

- 경기의 대상 스쿼드와 실제 엔트리를 분리합니다.
- U17 선수가 U18 경기에 참가해도 공식 소속은 자동 변경하지 않습니다.
- 출전, GPS, 경기 피드백은 해당 경기 세션의 선수 기록으로 연결합니다.

### 5.5 공지

- 역할 대상: 전체, 선수단, 학부모, 지도자
- 범위 대상: 전체 팀, 공식 스쿼드, 운영 그룹, 개별 사용자
- 여러 대상을 조합할 수 있고, 중복 수신자는 한 번만 계산합니다.
- 선수에게만 공개한 의료·코치 내부 메모는 학부모 공지에 자동 포함하지 않습니다.

## 6. 화면 정책

### 6.1 전역 범위 선택

- 사이드바의 팀 선택 영역 아래에 현재 범위를 표시합니다.
- 선택값: `전체 선수단`, `U16`, `U17`, `U18`, 운영 그룹.
- 선택한 범위는 일정, 선수단, 스쿼드 상태, 피드백, 경기 기록, 공지에 공통 적용합니다.
- 다른 범위의 정보가 함께 표시될 때는 `교차 스쿼드` 라벨로 이유를 설명합니다.
- 범위가 하나뿐인 팀에서는 선택기를 숨기고 팀명만 표시합니다.

### 6.2 일정

- 캘린더 색상은 일정 유형을 의미합니다.
- 카드 안의 칩은 대상 스쿼드와 운영 그룹을 의미합니다.
- 일정 만들기 순서는 `유형 → 대상 → 시간·장소 → 내용 → 공개 범위`입니다.
- 대상 선택 결과는 “U17 전체 24명 + U18 4명 - 재활조 2명 = 예상 26명”처럼 사람 수로 확인합니다.

### 6.3 세션 상세

- 상단에 계획 대상과 실제 참가자를 함께 표시합니다.
- 참가자 표에는 주 소속, 참가 방식, 컨디션, 부상·제한, GPS 상태, 피드백 상태를 표시합니다.
- 참가 방식: `기본`, `상위 합류`, `임시 합류`, `개인 추가`.
- 코치는 선수별 기록을 수정하지 않고도 필터를 통해 누락과 위험 선수를 먼저 찾을 수 있어야 합니다.

### 6.4 선수단과 선수 상세

- 선수단 기본 그룹은 공식 스쿼드입니다.
- 운영 그룹은 필터와 보조 칩으로 표시하며 별도의 선수 복사본을 만들지 않습니다.
- 선수 상세 상단에는 현재 주 소속, 참가 가능 스쿼드, 운영 그룹을 표시합니다.
- `소속 이력`과 `최근 교차 스쿼드 참가`를 별도 영역으로 제공합니다.
- 성장·피지컬·컨디션·부상·세션 기록은 동일 선수 ID를 기준으로 이어집니다.

### 6.5 공지

- 역할 탭은 `전체 / 선수단 / 학부모 / 지도자`를 유지합니다.
- 작성 화면에서 역할과 스쿼드·그룹 대상을 함께 선택합니다.
- 발송 전에 예상 수신 인원과 제외 대상을 확인합니다.

## 7. 권한과 개인정보

| 역할 | 기본 접근 범위 |
| --- | --- |
| 감독·관리자 | 팀 전체, 모든 스쿼드와 운영 그룹 |
| 스쿼드 코치 | 담당 스쿼드와 배정된 교차 세션 |
| 피지컬 코치 | 배정 세션의 피지컬·GPS·컨디션 데이터 |
| 메디컬 스태프 | 허용된 의료·부상 데이터와 제한 정보 |
| 선수 | 본인 데이터와 본인에게 공개된 세션·피드백 |
| 학부모 | 연결된 선수에게 공개 허용된 정보와 공지 |

- 의료 상세, 코치 내부 메모, 비공개 피드백은 역할별로 필드를 분리합니다.
- 소속 이동, 참가자 변경, 공개 범위 변경은 변경 이력을 남깁니다.
- 권한이 없는 스쿼드는 검색과 자동 완성 결과에도 노출하지 않습니다.

## 8. 주요 예외 처리

1. **U17 선수가 U18 훈련에 참가**
   주 소속은 U17로 유지하고 세션 참가 방식만 `상위 합류`로 저장합니다.

2. **시즌 중 U17에서 U18로 정식 승격**
   U17 소속 종료일과 U18 소속 시작일을 기록합니다. 과거 세션은 U17 기록으로 유지합니다.

3. **통합 훈련에서 일부 선수 제외**
   전체 또는 복수 스쿼드를 선택한 뒤 재활조나 개인 선수를 제외합니다.

4. **같은 선수가 여러 대상 규칙에 포함**
   대상 계산 단계에서 한 명으로 합칩니다.

5. **일정 대상과 실제 참가자가 다름**
   계획 변경으로 보지 않고 실제 참가자 목록에서 추가·제외 사유를 기록합니다.

6. **스쿼드 이름 변경**
   스쿼드 ID는 유지하고 이름의 적용 기간만 변경합니다.

## 9. 분석 기준

- 팀 전체 지표와 스쿼드 지표를 동시에 제공하되 현재 범위를 항상 화면에 표시합니다.
- 세션 부하와 컨디션 집계는 실제 참가자를 분모로 사용합니다.
- 교차 스쿼드 참가율은 `다른 공식 스쿼드의 세션에 참가한 횟수 / 전체 참가 세션 수`로 계산합니다.
- 선수 성장 추세는 공식 소속 변경과 무관하게 동일 선수의 시계열로 이어집니다.
- 통계 화면에는 집계 기간, 대상 범위, 실제 참가자 기준 여부를 함께 표시합니다.

## 10. 구현 완료 기준

- [ ] 팀 설정에서 통합·분리·혼합 운영 모드를 선택할 수 있다.
- [ ] 선수 한 명을 중복 등록하지 않고 여러 스쿼드 세션에 배정할 수 있다.
- [ ] 월·주 캘린더에서 유형 색상과 스쿼드 칩이 구분된다.
- [ ] 일정 대상과 실제 참가자를 별도로 확인할 수 있다.
- [ ] 세션 상세의 GPS·컨디션·부상·피드백이 선수별로 연결된다.
- [ ] 선수 상세에서 현재 소속, 운영 그룹, 소속 이력과 교차 참가 이력을 볼 수 있다.
- [ ] 공지 작성 시 역할과 스쿼드·그룹을 조합하고 예상 수신자를 확인할 수 있다.
- [ ] 역할별 개인정보 노출 제한과 변경 이력이 적용된다.
- [ ] 단일 스쿼드 팀에서는 추가 선택 UI가 숨겨진다.

## 11. 변경 관리

- 이 문서를 스쿼드 운영 규칙의 단일 기준으로 사용합니다.
- 데이터 모델, 화면, API 규칙이 바뀌면 이 문서를 먼저 수정합니다.
- 정책 변경 시 버전, 수정일, 영향 화면과 마이그레이션 필요 여부를 함께 기록합니다.
- Figma 화면에는 이 문서의 경로와 정책 버전을 표시합니다.
