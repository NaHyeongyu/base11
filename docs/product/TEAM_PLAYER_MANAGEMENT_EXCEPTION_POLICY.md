# 팀·선수 관리 예외 처리 정책

> 상태: 기준안 1.0
> 최종 수정: 2026-08-23
> 1차 사용자: 감독, 팀 매니저, 구단 관리자
> 적용 범위: 선수 등록, 명단 관리, 시즌·스쿼드, 파일 등록, 권한, 저장과 복구
> 상위 정책: [팀·선수 등록 및 관리 정책](./TEAM_PLAYER_MANAGEMENT_POLICY.md)
> 생애주기·인계 기준: [선수 생애주기·시즌 전환·진학 데이터 정책](./PLAYER_LIFECYCLE_DATA_POLICY.md)

## 1. 목적

정상 흐름에서 벗어난 상황이 생겼을 때 시스템이 임의로 판단하거나 기록을 잃지 않도록 처리 기준을 정합니다.

예외 화면은 단순히 `오류가 발생했습니다`라고 끝내지 않습니다. 다음 내용을 지도자에게 알려야 합니다.

- 무엇이 문제인지
- 지금 저장되었는지
- 계속 진행할 수 있는지
- 누가 어떤 조치를 해야 하는지
- 다시 시도해도 중복 등록되지 않는지

## 2. 처리 단계

모든 예외는 다음 네 단계 중 하나로 분류합니다.

| 단계 | 적용 기준 | 화면 행동 | 기록 |
| --- | --- | --- | --- |
| 차단 | 저장하면 정보·권한·이력이 충돌하는 경우 | 저장하지 않고 충돌 항목과 해결 방법 표시 | 시도 기록은 보안·운영상 필요한 경우만 저장 |
| 확인 후 진행 | 실제 팀 운영에서는 가능하지만 확인이 필요한 경우 | 영향 범위와 변경 사유를 확인한 뒤 저장 | 실행자, 시각, 사유, 변경 전·후 저장 |
| 등록 대기 | 필수 정보가 부족하지만 입력 내용을 버리면 안 되는 경우 | 명단에는 `등록 대기`로 보관하고 일정 대상에서 제외 | 작성자와 마지막 수정 시각 저장 |
| 자동 복구 | 통신·서버 문제처럼 같은 작업을 다시 실행해야 하는 경우 | 입력 보존, 재시도 제공, 중복 생성 방지 | 요청 식별값과 최종 처리 결과 저장 |

판단이 애매하면 데이터 충돌은 차단하고, 현실적인 운영 선택은 확인 후 진행으로 둡니다. 시스템이 선수의 신원, 소속이나 종료 사유를 추측해서 확정하지 않습니다.

## 3. 공통 처리 원칙

1. 저장에 실패했으면 성공한 것처럼 보이지 않습니다.
2. 사용자가 입력한 값은 가능한 한 화면에 그대로 남깁니다.
3. 한 번 누른 작업이 재시도 때문에 두 번 생성되지 않도록 요청 식별값을 사용합니다.
4. 일괄 작업은 적용 전 대상, 제외 대상과 충돌 건수를 먼저 보여줍니다.
5. 일부만 성공한 경우 성공·실패 대상을 분리해서 보여주고 실패 대상만 다시 시도할 수 있게 합니다.
6. 다른 사용자의 수정 내용을 조용히 덮어쓰지 않습니다.
7. 권한이 사라졌다면 저장은 막되 작성 중인 입력은 보존합니다.
8. 기록이 연결된 선수, 스쿼드, 시즌과 팀은 물리적으로 삭제하지 않습니다.
9. 종료·이동·복구처럼 과거 기록에 영향을 주는 작업에는 적용일과 사유를 받습니다.
10. 오류 문구는 선수나 담당자를 탓하지 않고 문제 항목과 다음 행동을 설명합니다.

## 4. 선수 등록과 중복

| 상황 | 처리 | 세부 규칙 |
| --- | --- | --- |
| 이름과 생년월일이 같은 선수가 같은 구단에 있음 | 차단 | 기존 선수 연결 또는 별도 선수 등록을 선택해야 함. 별도 등록에는 확인 사유 필요 |
| 이름만 같고 생년월일이 다름 | 확인 후 진행 | 두 선수 정보를 나란히 보여주고 신규 등록 가능 |
| 같은 선수가 같은 팀·시즌에 이미 등록됨 | 차단 | 기존 시즌 등록으로 이동 |
| 필수 기본 정보가 부족함 | 등록 대기 | 일정과 공식 명단 대상에서 제외 |
| 사진이나 연락처가 없음 | 확인 후 진행 | 등록을 막지 않음 |
| 일반적인 연령 범위를 벗어남 | 확인 후 진행 | 상향 출전 등 실제 운영을 위해 사유와 함께 허용 |
| 미래 생년월일 또는 잘못된 날짜 | 차단 | 문제가 있는 날짜 필드에서 바로 수정 |
| 선수 계정이 다른 선수와 이미 연결됨 | 차단 | 구단 관리자가 연결 상태를 확인. 자동 재연결 금지 |
| 중복 후보를 합치려 함 | 차단 후 관리자 처리 | 구단 관리자만 병합 가능. 연결된 시즌·세션·측정·계정을 비교한 뒤 실행 |

## 5. 소속·스쿼드·등번호

| 상황 | 처리 | 세부 규칙 |
| --- | --- | --- |
| 같은 날짜에 공식 주 소속이 두 개 생김 | 차단 | 기존 배정 종료일 또는 새 배정 시작일 수정 |
| 시즌 중 U17에서 U18로 이동 | 확인 후 진행 | 적용일 전날 기존 배정 종료, 적용일부터 새 배정 시작 |
| 훈련에만 다른 스쿼드와 참여 | 확인 후 진행 | 공식 소속을 바꾸지 않고 운영 그룹 또는 해당 일정의 게스트로 처리 |
| 같은 스쿼드·기간에 등번호가 겹침 | 차단 | 겹치는 선수와 기간을 표시. 등번호 미지정 상태의 등록 대기는 허용 |
| 과거 날짜로 소속·번호를 바꿈 | 확인 후 진행 | 기존 이력과 겹치면 차단, 겹치지 않으면 사유를 받고 저장 |
| 종료된 시즌 값을 수정 | 차단 후 관리자 정정 | 일반 편집은 읽기 전용. 구단 관리자 정정 절차와 변경 기록 필요 |
| 여러 선수를 한 번에 이동했으나 일부만 가능 | 확인 후 진행 | 적용 가능·제외·충돌 대상을 미리 보여주고 가능한 대상만 처리 |

## 6. 등록 종료·퇴단·복구

| 상황 | 처리 | 세부 규칙 |
| --- | --- | --- |
| 퇴단·이적·졸업 | 확인 후 진행 | 종료일과 사유 저장. 이후 일정에서는 제외하고 과거 기록은 유지 |
| 부상 또는 잠시 훈련 제외 | 확인 후 진행 | 등록을 종료하지 않고 참가 제한 또는 일시 중지 사용 |
| 종료일 이후 일정에 이미 배정됨 | 차단 | 영향을 받는 일정과 경기 수를 보여주고 제외·취소 후 종료 |
| 실수로 등록 종료 | 확인 후 진행 | 충돌하는 활성 등록이 없을 때만 복구. 복구일과 사유 기록 |
| 복구 기간이 다른 등록과 겹침 | 차단 | 겹치는 팀 등록 또는 시즌 등록을 먼저 정리 |
| 기록이 있는 선수를 삭제하려 함 | 차단 | `등록 종료` 또는 `보관`만 제공 |
| 기록이 전혀 없는 등록 대기 정보를 삭제 | 확인 후 진행 | 삭제 대상과 되돌릴 수 없음을 확인 |

## 7. 시즌·스쿼드 예외

| 상황 | 처리 | 세부 규칙 |
| --- | --- | --- |
| 운영 중 시즌이 이미 있는데 다른 시즌을 시작 | 차단 | 현재 시즌 종료 또는 새 시즌 시작일 조정 |
| 준비 중 시즌과 현재 시즌 기간이 일부 겹침 | 확인 후 진행 | 준비는 허용하되 운영 중 전환은 하나만 허용 |
| 보류 선수나 필수값 누락이 남은 채 시즌 시작 | 차단 | 누락·보류·충돌 목록을 해결한 뒤 시작 |
| 다음 시즌 등번호 충돌 | 차단 | 확정 전 충돌 해결. 준비 내용은 임시 저장 |
| 미래 일정이 남은 시즌을 종료 | 차단 | 연결된 일정과 경기를 이전·취소·완료한 뒤 종료 |
| 선수가 배정된 스쿼드를 삭제 | 차단 | `사용 종료`로 바꾸고 과거 명단에는 유지 |
| 활동 선수가 남은 팀을 보관 | 차단 | 시즌과 선수 등록을 먼저 종료 |
| 시즌을 잘못 종료 | 차단 후 관리자 정정 | 직접 되돌리기 대신 관리자 정정 절차 사용 |

## 8. 파일 일괄 등록 예외

| 상황 | 처리 | 세부 규칙 |
| --- | --- | --- |
| 지원하지 않는 파일·용량 초과 | 차단 | 허용 형식과 최대 크기를 업로드 전에 표시 |
| 필수 열이 없거나 열 이름이 모호함 | 차단 | 열 연결 화면에서 필수 열을 지정해야 검사 진행 |
| 일부 행만 오류 | 확인 후 진행 | 정상 행만 등록 가능. 오류 행은 제외하고 오류 파일로 내려받기 제공 |
| 파일 안에서 같은 선수가 반복됨 | 차단 | 반복 행끼리 묶어 기존 선수 연결·한 건만 등록·보류 중 선택 |
| 이전에 처리한 같은 파일을 다시 올림 | 차단 | 이전 처리 시각과 결과를 보여주고 실패 행만 재처리 가능 |
| 등록 도중 연결이 끊김 | 자동 복구 | 이미 처리된 행은 다시 만들지 않고 미처리·실패 행만 재시도 |
| 여러 행에 같은 값 오류 | 확인 후 진행 | 원본 파일을 덮어쓰지 않고 화면에서 일괄 수정 후 재검사 |

## 9. 권한과 동시 수정

| 상황 | 처리 | 세부 규칙 |
| --- | --- | --- |
| 담당 스쿼드 밖의 선수를 조회·수정 | 차단 | 검색과 자동 완성에서도 노출하지 않음 |
| 편집 중 역할 또는 담당 범위가 변경됨 | 차단 | 입력을 보존하고 필요한 역할과 요청 경로 표시 |
| 두 명이 같은 선수를 동시에 수정 | 차단 | 마지막으로 불러온 버전 이후 변경 내용을 비교하고 다시 불러오기 제공 |
| 마지막 구단 관리자를 비활성화하거나 권한 해제 | 차단 | 다른 구단 관리자를 먼저 지정 |
| 팀 매니저가 관리자 권한을 부여 | 차단 | 구단 관리자만 처리 가능 |
| 민감 연락처·의료 정보 내보내기 | 차단 또는 제한 | 기본 내보내기에서 제외. 별도 권한과 대상 확인 필요 |

## 10. 저장·통신 예외

| 상황 | 처리 | 세부 규칙 |
| --- | --- | --- |
| 네트워크가 끊기거나 시간 초과 | 자동 복구 | 입력 유지, `저장되지 않음` 표시, 같은 요청으로 재시도 |
| 서버 검증에서 충돌 발견 | 차단 | 화면의 최신 값과 충돌 대상을 다시 표시 |
| 일부 항목만 저장됨 | 자동 복구 | 성공·실패 항목을 구분하고 실패 항목만 재시도 |
| 저장 직후 화면을 닫으려 함 | 차단 | 저장 완료까지 기다리거나 입력을 유지한 채 나가기 선택 |
| 목록은 저장됐지만 새로고침이 늦음 | 자동 복구 | 성공 응답을 기준으로 화면을 먼저 갱신하고 백그라운드 재조회 |

오프라인에서 선수 등록을 새로 확정하는 기능은 1차 범위에 넣지 않습니다. 연결이 끊기면 작성 내용만 보존하고 온라인 상태에서 저장합니다.

## 11. 화면 문구 기준

권장 형식은 `문제 + 영향 + 다음 행동`입니다.

- `11번은 현재 U18 김민수 선수에게 배정되어 있습니다. 번호 또는 적용일을 바꿔 주세요.`
- `변경 내용을 저장하지 못했습니다. 입력한 내용은 남아 있습니다. 다시 시도해 주세요.`
- `다른 사용자가 이 선수 정보를 먼저 수정했습니다. 변경 내용을 확인한 뒤 다시 저장해 주세요.`
- `종료일 이후 일정 3건에 이 선수가 포함되어 있습니다. 일정에서 제외한 뒤 등록을 종료할 수 있습니다.`

사용하지 않는 문구:

- `알 수 없는 오류가 발생했습니다.`
- `잘못된 요청입니다.`
- `AI가 충돌을 해결했습니다.`
- `스마트하게 자동 처리됩니다.`

## 12. 변경 기록과 되돌리기

다음 예외 처리에는 실행자, 시각, 대상, 변경 전·후, 적용일과 사유를 남깁니다.

- 중복 후보를 별도 선수로 등록
- 과거 날짜 소속·등번호 변경
- 등록 종료와 복구
- 종료 시즌 정정
- 역할과 담당 범위 변경
- 중복 선수 병합
- 일괄 등록 일부 적용

일반 화면에서 안전하게 되돌릴 수 있는 것은 등록 종료 복구와 임시 입력 취소로 제한합니다. 중복 병합, 기록 삭제와 종료 시즌 정정은 관리자 복구 절차를 사용합니다.

## 13. 1차 구현 완료 조건

- [ ] 모든 저장 작업에 저장 중·저장됨·저장 실패 상태가 있다.
- [ ] 중복 선수, 주 소속 기간과 등번호 충돌은 저장 전에 확인된다.
- [ ] 필수 정보가 부족한 선수는 등록 대기로 보존된다.
- [ ] 파일 등록은 정상 행과 오류 행을 분리해 처리할 수 있다.
- [ ] 같은 파일이나 요청을 재시도해도 중복 선수·등록이 생기지 않는다.
- [ ] 동시 수정 시 다른 사람의 변경을 덮어쓰지 않는다.
