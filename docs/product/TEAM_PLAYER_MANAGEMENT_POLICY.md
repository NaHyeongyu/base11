## 1. 목적

이 문서는 BASE11에서 팀을 만들고 선수를 등록한 뒤, 시즌과 스쿼드가 바뀌어도 기록을 잃지 않고 관리하는 방법을 정합니다.

다음 질문에 대한 기준입니다.

- 팀과 시즌을 같은 것으로 볼 것인가
- 선수를 등록할 때 무엇이 필요한가
- 선수 계정이 없어도 등록할 수 있는가
- U16, U17, U18 이동을 어떻게 기록할 것인가
- 등번호, 포지션과 학년이 바뀌면 과거 기록을 어떻게 남길 것인가
- 휴식, 부상, 퇴단과 시즌 종료를 어떻게 구분할 것인가
- 누가 선수 정보와 팀 설정을 수정할 수 있는가

## 2. 이번에 확정하는 기본 원칙

1. 팀, 시즌과 스쿼드를 서로 다른 정보로 관리합니다.
2. 선수는 팀이나 로그인 계정에 종속되지 않는 하나의 인물 정보로 관리합니다.
3. 선수는 앱 계정이 없어도 팀 매니저가 등록할 수 있습니다.
4. 한 선수를 시즌마다 새로 만들지 않습니다. 시즌 등록만 새로 만듭니다.
5. 공식 스쿼드, 등번호, 학년과 포지션은 시즌 및 적용 기간에 따라 기록합니다.
6. 선수의 부상·컨디션·참가 가능 여부를 선수 등록 상태와 섞지 않습니다.
7. 퇴단하거나 시즌이 끝난 선수도 과거 세션과 기록에서 삭제하지 않습니다.
8. 이미 세션 기록이 있는 선수는 삭제하지 않고 등록 종료 또는 보관 처리합니다.
9. 이름이 같다는 이유로 선수를 자동으로 합치지 않습니다.
10. 선수 등록과 소속 변경은 누가 언제 바꿨는지 남깁니다.
11. 예외는 `차단`, `확인 후 진행`, `등록 대기`, `자동 복구`로 구분합니다.
12. 저장 실패, 권한 변경과 동시 수정이 발생해도 작성 중인 입력을 가능한 한 보존합니다.

## 3. 정보 구조

```text
구단·기관
└─ 팀
   ├─ 시즌
   │  ├─ 공식 스쿼드
   │  │  └─ 선수 시즌 등록
   │  └─ 운영 그룹
   ├─ 선수 등록 이력
   └─ 스태프 배정과 권한

선수 원본
├─ 기본 신원
├─ 팀 등록 이력
├─ 시즌 등록과 등번호
├─ 공식 스쿼드 배정 이력
├─ 계정 연결(선택)
└─ 세션·측정·부상·피드백 기록
```

### 3.1 구단·기관

여러 팀을 소유하고 관리하는 최상위 단위입니다.

- 예: `FC 안양 아카데미`, `○○고등학교 축구부`, `○○FC 유소년팀`
- 구단 이름, 엠블럼, 대표 연락처, 기본 지역과 시간대를 관리합니다.
- 여러 팀을 운영하지 않는 경우에도 내부적으로는 하나의 구단 아래 하나의 팀을 둡니다.

### 3.2 팀

여러 시즌 동안 유지되는 지도자 운영 단위입니다.

- 예: `FC 안양 고등부`, `○○고 축구부`
- 팀은 매년 새로 만들지 않습니다.
- 팀에 시즌, 공식 스쿼드, 선수와 스태프가 연결됩니다.
- 팀 상태는 `운영 중` 또는 `보관`만 사용합니다.

현재 데이터의 `FC 안양 U18 · 2026`은 앞으로 다음처럼 분리합니다.

| 구분 | 값 |
| --- | --- |
| 구단 | FC 안양 아카데미 |
| 팀 | FC 안양 고등부 |
| 시즌 | 2026 시즌 |
| 공식 스쿼드 | U18 |

### 3.3 시즌

선수 명단, 등번호, 학년과 경기 기록을 묶는 기간입니다.

- 기본 기간은 한 해지만 시작일과 종료일을 직접 정할 수 있습니다.
- 상태는 `준비 중`, `운영 중`, `종료`입니다.
- 한 팀에는 운영 중 시즌을 하나만 둡니다.
- 다음 시즌을 준비 중으로 미리 만들 수 있습니다.
- 종료된 시즌은 기본적으로 읽기 전용입니다.
- 오류 수정은 권한이 있는 관리자만 가능하며 변경 이력을 남깁니다.

### 3.4 공식 스쿼드

시즌 안에서 선수의 공식 소속을 나누는 단위입니다.

- 예: `U16`, `U17`, `U18`, `A팀`, `B팀`
- 공식 스쿼드는 시즌마다 만듭니다.
- 한 선수는 같은 날짜에 하나의 주 소속 스쿼드만 가집니다.
- 시즌 중 정식 승격이나 이동이 있으면 기존 배정을 종료하고 새 배정을 시작합니다.
- 다른 스쿼드 훈련에 한두 번 참가한 것은 공식 소속 변경으로 처리하지 않습니다.

### 3.5 운영 그룹

훈련이나 관리 목적의 임시 그룹입니다.

- 예: `재활조`, `GK 그룹`, `1군 준비조`, `세트피스 A조`
- 한 선수는 여러 운영 그룹에 동시에 속할 수 있습니다.
- 시작일과 종료일을 기록합니다.
- 운영 그룹은 공식 소속과 등번호를 바꾸지 않습니다.

### 3.6 선수 원본

선수 한 사람을 나타내는 변하지 않는 기준 정보입니다.

- 선수 원본은 구단·기관 안에서만 공유합니다. 서로 다른 구단의 선수 정보는 검색하거나 자동 연결하지 않습니다.
- 팀이나 시즌이 바뀌어도 같은 선수 ID를 사용합니다.
- 이름 변경이나 오기 수정은 원본을 수정하고 변경 이력을 남깁니다.
- 선수 원본과 로그인 계정은 별도입니다.
- 선수 앱을 사용하지 않는 선수도 등록과 기록 관리가 가능합니다.

### 3.7 팀 등록

선수와 팀의 관계를 나타냅니다.

- 입단일, 등록 상태, 종료일과 종료 사유를 관리합니다.
- 팀 등록 상태는 `등록 대기`, `활동 중`, `일시 중지`, `종료`입니다.
- `일시 중지`와 `종료`는 새로운 일정 대상에서 기본 제외됩니다.
- 부상과 재활은 팀 등록 상태가 아닙니다. 부상 선수라도 팀 등록은 `활동 중`일 수 있습니다.

### 3.8 선수 시즌 등록

특정 시즌의 명단에 선수를 포함시키는 정보입니다.

- 시즌, 선수, 주 소속 스쿼드, 등번호, 학년, 주 포지션과 등록 기간을 관리합니다.
- 같은 선수에게 시즌마다 새 시즌 등록을 만듭니다.
- 지난 시즌의 등번호와 학년은 그대로 보존합니다.
- 다음 시즌으로 선수를 넘길 때 선수 원본은 복사하지 않고 새 시즌 등록만 만듭니다.

## 4. 선수 정보 항목

정보는 한 화면에 모두 넣지 않고 관리 목적에 따라 나눕니다.

### 4.1 기본 신원

| 항목 | 등록 시점 | 규칙 |
| --- | --- | --- |
| 이름 | 필수 | 실제 팀에서 사용하는 한글 이름 |
| 생년월일 | 필수 | 중복 확인과 연령 확인 기준 |
| 영문 이름 | 선택 | 국제대회·장비 데이터 매칭용 |
| 프로필 사진 | 선택 | 선수 식별용, 공개 범위 별도 |
| 내부 선수 번호 | 자동 | 시스템이 발급하며 수정하지 않음 |

주민등록번호, 여권번호와 상세 집 주소는 기본 제품에서 수집하지 않습니다. 향후 공식 대회 등록에 필요한 경우 별도 권한과 보관 정책을 정한 뒤 추가합니다.

### 4.2 축구 정보

| 항목 | 등록 시점 | 규칙 |
| --- | --- | --- |
| 주 포지션 | 시즌 활성 전 필수 | GK, DF, MF, FW |
| 세부 포지션 | 선택 | CB, FB/WB, DM/CM/AM, W, ST 등 복수 선택 |
| 주발 | 선택 | 오른발, 왼발, 양발, 미확인 |
| 등번호 | 선택 | 스쿼드와 적용 기간 기준 1~99 |
| 학년 | 시즌 활성 전 필수 | 해당 시즌의 학년으로 저장 |
| 학교 | 선택 | 시즌이 바뀌면 확인 필요 |

등번호는 팀 전체가 아니라 `시즌 + 공식 스쿼드 + 적용 기간` 안에서만 중복을 막습니다. 등번호가 없는 연습생이나 새로 합류한 선수도 등록할 수 있습니다.

### 4.3 팀 등록 정보

- 입단일
- 현재 등록 상태
- 등록 상태 적용일
- 종료일
- 종료 사유: 졸업, 이적, 방출, 자진 퇴단, 팀 이동, 기타
- 내부 관리 메모

종료 사유는 지도자 화면에서만 보며 선수 공개 정보에 포함하지 않습니다.

### 4.4 연락 정보

현재 우선순위에서는 선택 정보로 둡니다.

- 선수 연락처
- 비상 연락처 이름과 관계
- 비상 연락처 전화번호
- 이메일

연락처는 팀 매니저와 허용된 관리자만 수정합니다. 일반 코치는 기본적으로 연락처를 조회하지 않습니다. 선수·학부모 계정 연결은 별도 단계이며 선수 등록의 필수 조건이 아닙니다.

### 4.5 신체·측정 정보

신장, 체중과 피지컬 측정값은 선수 기본 정보에 현재 값 하나만 저장하지 않습니다.

- 측정값
- 단위
- 측정일
- 측정자
- 측정 방법 또는 장비
- 메모

선수 목록에는 가장 최근 값을 보여주되 과거 측정값은 시계열로 유지합니다.

### 4.6 의료·컨디션 정보

기본 선수 정보와 분리합니다.

- 팀 매니저는 상세 진단 내용을 수정하지 않습니다.
- 코치는 `전체 참가`, `제한 참가`, `참가 불가`, `확인 필요`와 같은 운영 판단만 봅니다.
- 상세 부상·진단 정보는 메디컬 권한 범위에서 관리합니다.
- 부상 상태로 선수 등록 상태를 변경하지 않습니다.

## 5. 상태 정의

### 5.1 팀

| 상태 | 의미 | 화면 동작 |
| --- | --- | --- |
| 운영 중 | 현재 사용하는 팀 | 일정·선수·스태프 관리 가능 |
| 보관 | 더 이상 운영하지 않는 팀 | 읽기 전용, 기본 목록에서 숨김 |

### 5.2 시즌

| 상태 | 의미 | 화면 동작 |
| --- | --- | --- |
| 준비 중 | 다음 시즌 명단과 설정 준비 | 일정·공식 기록 생성 제한 |
| 운영 중 | 현재 시즌 | 모든 운영 기능 사용 |
| 종료 | 시즌 완료 | 읽기 전용, 정정만 허용 |

### 5.3 팀 등록

| 상태 | 의미 | 일정 대상 포함 |
| --- | --- | --- |
| 등록 대기 | 기본 정보만 입력된 상태 | 제외 |
| 활동 중 | 현재 팀에서 활동 | 포함 |
| 일시 중지 | 장기 부재 등으로 임시 제외 | 기본 제외 |
| 종료 | 팀과의 관계가 끝남 | 제외 |

`부상`, `재활`, `컨디션 저하`는 이 상태에 사용하지 않습니다.

## 6. 팀 최초 설정 흐름

팀을 처음 사용하는 순서는 다음으로 고정합니다.

1. 구단·기관 기본 정보 확인
2. 계속 유지될 팀 생성
3. 현재 시즌 기간 설정
4. 공식 스쿼드 생성
5. 감독, 팀 매니저와 스태프 초대
6. 선수 개별 등록 또는 일괄 등록
7. 중복·누락 확인
8. 시즌 명단 활성화

팀 생성 시 선수·학부모 초대 링크를 먼저 요구하지 않습니다.

## 7. 선수 개별 등록 흐름

### 7.1 1단계: 중복 확인

팀 매니저가 이름과 생년월일을 입력하면 다음을 확인합니다.

- 현재 팀의 활동 중·종료 선수
- 같은 구단의 다른 팀 선수
- 이름과 생년월일이 모두 같은 선수
- 이름이 비슷하고 생년월일 또는 연락처가 같은 선수

일치 가능성이 있으면 기존 선수 연결, 새 선수 등록 또는 관리자 확인 중 하나를 선택합니다. 시스템이 자동으로 합치지 않습니다.

### 7.2 2단계: 기본 정보

필수 입력은 다음 네 가지입니다.

1. 이름
2. 생년월일
3. 팀 입단일
4. 현재 시즌

이 단계에서 저장하면 `등록 대기` 상태가 됩니다.

### 7.3 3단계: 시즌 명단

활성화를 위해 다음을 입력합니다.

- 주 소속 스쿼드
- 학년
- 주 포지션
- 등번호(선택)

입력이 끝나면 `활동 중`으로 전환하고 일정과 세션 대상에서 선택할 수 있습니다.

### 7.4 4단계: 추가 정보

주발, 세부 포지션, 학교, 연락처, 사진과 계정 연결은 나중에 입력할 수 있습니다. 추가 정보가 비어 있어도 선수 운영은 막지 않습니다.

## 8. 선수 일괄 등록

일괄 등록은 엑셀·CSV 가져오기를 기본으로 합니다.

1. BASE11 양식 내려받기
2. 파일 선택
3. 열 이름 연결 확인
4. 필수값·형식·중복 검사
5. `등록 가능`, `확인 필요`, `등록 불가` 행 분리
6. 팀 매니저가 확인 후 등록 실행
7. 등록 결과와 제외 행 파일 제공

필수 열은 이름, 생년월일, 입단일, 시즌, 스쿼드, 학년과 주 포지션입니다. 등번호는 선택입니다.

다음 경우 바로 등록하지 않습니다.

- 필수 정보가 없음
- 생년월일 형식이 잘못됨
- 존재하지 않는 시즌 또는 스쿼드
- 같은 스쿼드·기간에 등번호가 중복됨
- 기존 선수일 가능성이 높음

파일을 올리는 즉시 데이터를 반영하지 않고 반드시 검토 화면을 거칩니다.

## 9. 선수 정보 수정

### 9.1 원본 정보 수정

이름과 생년월일 수정은 팀 매니저 또는 관리자만 가능합니다. 이미 세션 기록이 있으면 수정 사유를 입력하고 변경 이력을 남깁니다.

### 9.2 시즌 정보 수정

- 단순 오기: 현재 시즌 등록을 정정
- 등번호 변경: 기존 적용 기간 종료 후 새 번호 시작
- 학년 오기: 사유와 함께 정정
- 주 포지션 변경: 현재 값 변경과 변경일 기록
- 공식 스쿼드 이동: 기존 배정 종료 후 새 배정 시작

과거 시즌의 값은 현재 정보로 덮어쓰지 않습니다.

### 9.3 여러 선수 일괄 변경

다음 작업만 일괄 변경을 허용합니다.

- 공식 스쿼드 이동
- 운영 그룹 추가·제외
- 시즌 등록 상태 변경
- 시즌 종료 처리

이름, 생년월일, 연락처와 의료 정보는 일괄 수정하지 않습니다.

## 10. 시즌 전환

세부적인 데이터 연결, 졸업생 보관과 다른 학교 인계는 [선수 생애주기·시즌 전환·진학 데이터 정책](./PLAYER_LIFECYCLE_DATA_POLICY.md)을 따릅니다.

다음 시즌 준비는 복사가 아니라 기존 선수를 새 시즌에 다시 등록하는 작업입니다.

1. 다음 시즌을 `준비 중`으로 생성
2. 공식 스쿼드 구성
3. 이전 시즌 선수 목록 불러오기
4. 선수별 처리 선택
   - 다음 시즌 등록
   - 졸업
   - 이적·퇴단
   - 결정 보류
5. 다음 시즌 스쿼드, 학년, 포지션과 등번호 입력
6. 누락과 중복 확인
7. 시즌 시작일에 새 시즌을 `운영 중`으로 전환
8. 이전 시즌을 `종료`로 전환

복사하는 정보:

- 선수 원본
- 기본 축구 정보
- 허용된 연락 정보

새로 확인하는 정보:

- 공식 스쿼드
- 학년
- 등번호
- 학교
- 시즌 등록 상태

복사하지 않는 정보:

- 지난 시즌 일정과 참가자
- 지난 시즌 컨디션
- 지난 시즌 등번호를 새 시즌 확정값으로 자동 적용
- 종료된 운영 그룹

## 11. 퇴단·졸업·이적

- 팀 등록 종료일과 종료 사유를 필수로 입력합니다.
- 종료일 이후의 새 일정 대상에서 제외합니다.
- 종료일 이전의 세션, 측정, 부상과 메모는 유지합니다.
- 실수로 종료한 경우 관리자만 복구할 수 있으며 복구 이력을 남깁니다.
- 같은 구단의 다른 팀으로 이동하는 경우 선수 원본은 유지하고 새 팀 등록을 만듭니다.
- 다른 구단으로 이적하는 경우에는 상대 구단에 선수 정보를 자동으로 넘기지 않습니다. 구단 간 기록 이전은 별도 동의와 이전 정책을 만든 뒤 지원합니다.
- 새 학교·구단은 유효한 인계 건과 범위별 동의가 있을 때만 출신팀 확인본을 볼 수 있습니다.
- 출신팀 확인본은 읽기 전용이며 새 학교가 만든 현재 정보와 분리합니다.
- 졸업생을 다시 등록할 때 새 선수를 만들지 않습니다.

## 12. 중복 선수 처리

### 12.1 중복 후보 기준

- 이름 정규화 값 + 생년월일 일치
- 생년월일 + 연락처 일치
- 영문 이름 + 생년월일 일치
- 외부 장비 선수 ID 일치

### 12.2 병합 정책

- 병합은 같은 구단 안에서만 가능하며 구단 관리자만 할 수 있습니다.
- 병합 전에 양쪽 선수의 시즌, 세션, 측정, 부상과 계정 연결을 비교합니다.
- 기준 선수를 선택하고 다른 선수의 기록을 기준 선수로 이동합니다.
- 병합 전후 ID와 실행자를 기록합니다.
- 병합은 일반 화면에서 즉시 되돌리지 않으며 관리자 복구 절차를 둡니다.

## 13. 선수 계정 연결

- 선수 등록과 앱 계정 생성은 별개입니다.
- 팀 매니저가 먼저 선수를 등록한 뒤 필요할 때 계정을 연결합니다.
- 계정 연결 전에도 모든 코치 운영 기능을 사용할 수 있습니다.
- 한 선수 원본에는 현재 사용 중인 선수 계정을 하나만 연결합니다.
- 잘못 연결한 계정은 관리자 확인 후 해제합니다.
- 선수·학부모 앱 기능은 현재 우선순위에서 제외합니다.

## 16. 변경 이력과 삭제

다음 변경은 반드시 기록합니다.

- 이름과 생년월일
- 팀 등록 상태와 종료 사유
- 시즌 등록
- 공식 스쿼드 이동
- 등번호
- 스태프 역할과 담당 범위
- 연락처와 계정 연결
- 중복 선수 병합

변경 기록에는 실행자, 실행 시각, 변경 전 값, 변경 후 값과 사유를 저장합니다.

삭제 규칙:

- 세션·측정·부상·피드백이 없는 `등록 대기` 선수만 삭제할 수 있습니다.
- 기록이 하나라도 있으면 삭제 대신 등록 종료 처리합니다.
- 시즌과 팀은 기록이 있으면 삭제하지 않고 종료 또는 보관합니다.
- 개인정보 보관 기간과 파기 기준은 별도의 법률·운영 검토 후 정합니다. 임의의 기간을 제품에 고정하지 않습니다.

## 17. 입력 검증

- 이름: 앞뒤 공백 제거, 2~50자
- 생년월일: 미래 날짜 금지, 일반적인 유소년 연령을 벗어나면 경고 후 확인
- 입단일: 팀 등록 종료일보다 늦을 수 없음
- 시즌: 시작일이 종료일보다 늦을 수 없음
- 등번호: 1~99 또는 미지정
- 등번호 중복: 같은 시즌·스쿼드·기간 안에서 금지
- 주 소속 스쿼드: 같은 날짜에 두 개 이상 금지
- 연락처: 국가번호와 숫자를 정규화해 저장
- 상태 변경: 적용일과 사유가 필요한 경우 저장 전 확인

경고와 차단을 구분합니다. 예를 들어 연령 범위가 특이한 경우는 경고하지만, 등번호와 주 소속 기간이 실제로 겹치는 경우는 저장을 막습니다.

## 18. 현재 구현과의 차이

현재 구현은 다음 점에서 이 정책을 만족하지 못합니다.

1. 팀에 시즌과 연령이 직접 들어 있어 매년 팀을 새로 만들게 됩니다.
2. 선수와 스태프가 같은 팀 구성원 구조에 있고 선수 등록에 사용자 계정이 필요합니다.
3. 시즌, 공식 스쿼드와 선수 시즌 등록 정보가 없습니다.
4. 등번호가 팀 전체에서 하나만 허용되어 여러 스쿼드 운영에 맞지 않습니다.
5. 포지션, 학년과 등번호의 변경 이력을 남길 수 없습니다.
6. 선수 목록과 상세 화면은 샘플 데이터이며 실제 등록·수정 API가 없습니다.
7. `active` 값 하나로 활동, 일시 중지와 종료 사유를 구분할 수 없습니다.
8. 팀 매니저 역할과 권한이 없습니다.

따라서 기존 팀·선수 테이블을 그대로 확장하기보다 시즌과 선수 등록 구조를 먼저 분리한 뒤 화면을 연결합니다.

## 19. 구현 우선순위

### 1단계: 운영 기반

- 구단·팀 분리
- 시즌과 공식 스쿼드
- 선수 원본과 팀 등록 분리
- 팀 매니저 역할
- 선수 개별 등록, 조회, 수정과 종료
- 소속·등번호 이력

### 2단계: 실제 팀 전환

- 엑셀·CSV 일괄 등록
- 중복 후보 확인
- 이전 시즌에서 다음 시즌 명단 구성
- 운영 그룹
- 변경 이력 화면

### 3단계: 전문 기록 연결

- 신체 측정 시계열
- 세션 참가자 연결
- GPS 외부 선수 ID 연결
- 메디컬 접근 범위

### 현재 보류

- 선수·학부모 앱 가입 유도
- 선수용 초대 링크 중심 흐름
- 자동 훈련 처방과 추천 문구
- 홍보성 팀 프로필과 소셜 기능

## 20. 완료 기준

- [ ] 팀을 시즌과 분리해 여러 해 동안 유지할 수 있다.
- [ ] 한 시즌 안에 여러 공식 스쿼드를 만들 수 있다.
- [ ] 선수 계정 없이 선수를 등록할 수 있다.
- [ ] 한 선수를 복제하지 않고 다음 시즌과 다른 스쿼드에 연결할 수 있다.
- [ ] 등번호, 학년, 포지션과 소속 변경 이력을 볼 수 있다.
- [ ] 선수 개별 등록과 일괄 등록에서 중복 후보를 확인할 수 있다.
- [ ] 부상 상태가 선수 등록 상태를 바꾸지 않는다.
- [ ] 종료 선수가 과거 세션과 기록에 그대로 남는다.
- [ ] 팀 매니저가 선수 명단과 시즌 구성을 관리할 수 있다.
- [ ] 민감 정보는 역할별로 제한된다.
- [ ] 주요 변경에 실행자, 시각, 변경 전·후와 사유가 남는다.
