## 1. 목적

감독과 팀 매니저가 팀, 시즌, 스쿼드와 선수 명단을 한 곳에서 관리할 수 있게 합니다. 선수 계정 가입이나 훈련 데이터 입력보다 먼저 팀의 기준 정보와 현재 명단을 정확하게 만드는 것이 이 기능의 목적입니다.

## 2. 해결할 문제

현재 구현에는 다음 문제가 있습니다.

1. 팀에 시즌과 연령이 직접 포함되어 시즌마다 팀을 다시 만들어야 합니다.
2. 선수 등록이 사용자 계정과 연결되어 계정이 없는 선수를 먼저 등록할 수 없습니다.
3. U16, U17, U18과 시즌별 명단을 저장하는 구조가 없습니다.
4. 등번호, 학년, 포지션과 소속 변경 이력을 남길 수 없습니다.
5. 선수 목록과 상세 화면이 샘플 데이터이므로 실제 등록·수정·종료가 되지 않습니다.
6. 팀 매니저 역할이 없어 선수 정보 관리 책임이 코치와 관리자 사이에 섞여 있습니다.

## 3. 목표

- 팀 매니저가 선수 한 명을 1분 안에 등록할 수 있습니다.
- 30명 명단 파일을 10분 안에 검토하고 등록할 수 있습니다.
- 같은 선수를 시즌이나 스쿼드마다 다시 만들지 않습니다.
- 현재 명단과 지난 시즌 명단을 분리해서 볼 수 있습니다.
- 선수의 입단, 소속 이동, 등번호 변경과 종료 이력을 확인할 수 있습니다.
- 권한이 없는 사용자는 연락처와 의료 상세에 접근할 수 없습니다.
- 모든 주요 변경에 실행자, 시각, 변경 전·후와 사유가 남습니다.

## 4. 현재 범위

### 포함

- 구단·기관 기본 정보 조회
- 장기간 유지되는 팀 생성·수정·보관
- 시즌 생성·시작·종료
- 공식 스쿼드 생성·수정·정렬
- 팀 매니저와 스태프 배정
- 선수 개별 등록
- 선수 엑셀·CSV 일괄 등록
- 선수 검색, 필터와 저장된 보기
- 선수 기본 정보와 축구 정보 수정
- 팀 등록, 시즌 등록과 공식 스쿼드 이력
- 등번호와 포지션 변경
- 선수 등록 일시 중지·종료·복구
- 다음 시즌 명단 구성
- 중복 후보 검토와 구단 관리자 병합
- 주요 변경 이력

### 제외

- 선수·학부모 앱 가입 유도
- 선수용 초대 링크 중심 등록
- 자동 훈련 처방과 자동 작성 문구
- 경기·훈련 세션 편집
- 상세 의료 기록 입력
- 외부 협회 선수 등록 자동 연동
- 구단 간 선수 기록 자동 이전
- 급여, 계약금과 회계 관리

## 5. 기준 사용자

### 5.1 팀 매니저

주 사용자입니다.

- 팀, 시즌과 스쿼드를 준비합니다.
- 선수 정보를 등록하고 누락을 정리합니다.
- 입단, 등번호 변경, 소속 이동과 퇴단을 처리합니다.
- 엑셀 명단을 가져오고 중복 후보를 확인합니다.
- 스태프 초대와 활성 상태를 관리합니다.

### 5.2 감독

- 시즌과 스쿼드 구성을 확인하고 변경합니다.
- 선수 등록과 종료를 직접 처리하거나 팀 매니저에게 요청합니다.
- 코치의 담당 스쿼드와 접근 범위를 확인합니다.

### 5.3 담당 코치

- 담당 스쿼드 선수 명단과 기본 축구 정보를 봅니다.
- 담당 선수의 포지션과 운영 그룹을 수정합니다.
- 이름, 생년월일, 연락처와 팀 등록 종료는 직접 수정하지 않습니다.

### 5.4 구단 관리자

- 여러 팀을 만들고 보관합니다.
- 중복 선수를 병합합니다.
- 팀 매니저와 스태프 권한을 최종 관리합니다.
- 종료된 시즌의 정정을 처리합니다.

## 6. 제품 구조

### 6.1 주 메뉴

```text
선수단
├─ 현재 명단
├─ 등록 대기
└─ 종료 선수

팀 관리
├─ 팀 정보
├─ 시즌·스쿼드
├─ 운영 그룹
├─ 스태프·권한
├─ 변경 기록
└─ 팀 보관
```

선수 목록은 `선수단` 메뉴에만 둡니다. 팀 관리 화면에 같은 목록을 다시 만들지 않습니다.

### 6.2 전역 범위

- 상단에서 현재 팀과 시즌을 확인합니다.
- 선수단에서는 공식 스쿼드를 필터로 선택합니다.
- 시즌을 바꾸면 명단, 등번호, 학년과 소속 표시가 해당 시즌 기준으로 바뀝니다.
- 종료된 시즌을 보고 있을 때는 `종료된 시즌 · 읽기 전용`을 화면 상단에 표시합니다.

## 8. 상세 요구사항

### 8.1 PL-01 선수단 목록

#### 화면 목적

현재 시즌의 선수 명단과 정보 누락을 확인하고 등록·수정 화면으로 들어갑니다.

#### 기본 구성

1. 현재 팀·시즌·스쿼드 범위
2. 화면 제목과 `선수 등록` 주 버튼
3. 검색과 필터
4. 목록 상태 탭
5. 선수 표
6. 선택한 선수 일괄 작업

#### 기본 열

- 선수 이름과 사진 또는 등번호
- 주 소속 스쿼드
- 등번호
- 학년
- 주 포지션
- 팀 등록 상태
- 참가 가능 상태
- 정보 누락
- 마지막 수정일

#### 기본 정렬

1. 등록 대기와 정보 누락
2. 공식 스쿼드 표시 순서
3. 등번호 오름차순
4. 이름 오름차순

#### 필터

- 시즌
- 공식 스쿼드
- 팀 등록 상태
- 주 포지션
- 운영 그룹
- 정보 누락

#### 일괄 작업

- 공식 스쿼드 변경
- 운영 그룹 추가·제외
- 시즌 등록 상태 변경
- 시즌 종료 처리

이름, 생년월일, 연락처와 의료 정보는 일괄 수정할 수 없습니다.

#### 빈 상태

- 현재 시즌 없음: `먼저 현재 시즌을 만들어 주세요.`
- 공식 스쿼드 없음: `선수를 등록하기 전에 공식 스쿼드를 만들어 주세요.`
- 선수 없음: `등록된 선수가 없습니다.` + `선수 등록`, `파일로 등록`
- 검색 결과 없음: 필터 초기화 제공

### 8.2 PL-02 선수 개별 등록

#### 화면 방식

페이지 안의 3단계 등록 흐름을 사용합니다. 작은 팝업 안에 모든 항목을 넣지 않습니다.

#### 1단계: 중복 확인

- 이름
- 생년월일
- 기존 선수 후보
- `기존 선수 연결` 또는 `새 선수 등록`

#### 2단계: 기본 정보

- 이름
- 생년월일
- 영문 이름(선택)
- 입단일
- 현재 시즌

이 단계에서 저장하면 `등록 대기`가 됩니다.

#### 3단계: 시즌 명단

- 공식 스쿼드
- 학년
- 주 포지션
- 세부 포지션(선택)
- 등번호(선택)
- 주발(선택)

`명단에 등록`을 실행하면 `활동 중`이 되고 일정 대상에서 선택할 수 있습니다.

#### 취소와 임시 저장

- 2단계부터 임시 저장 가능
- 임시 저장 후 선수단 `등록 대기` 탭에 표시
- 저장되지 않은 변경이 있으면 나가기 전에 확인

### 8.3 PL-03·04 선수 일괄 등록

#### 단계

1. 양식 내려받기
2. 파일 선택
3. 열 연결
4. 검사 결과
5. 중복 후보 처리
6. 등록 결과

#### 검사 결과 구분

- 등록 가능
- 확인 필요
- 등록 불가

#### 행 단위 수정

- 잘못된 셀을 표 안에서 수정할 수 있습니다.
- 오류가 있는 행만 필터링할 수 있습니다.
- 여러 행에서 같은 오류가 있으면 일괄 적용을 제공합니다.
- 등록 불가 행이 있어도 등록 가능한 행만 먼저 등록할 수 있습니다.

#### 등록 결과

- 등록 완료 수
- 기존 선수 연결 수
- 등록 대기 수
- 제외 수
- 제외 행 파일 내려받기

### 8.4 PL-05 선수 상세

선수 상세는 기본 프로필이 아니라 훈련·경기·성장·피지컬·컨디션·부상·상담·피드백·소속 이력을 연결하는 전체 기록 허브로 운영합니다. 상세 정보 구조, 권한과 예외 기준은 [선수 상세 전체 기록 허브 기획서](./PLAYER_DETAIL_HUB_PRD.md)를 따릅니다.

#### 상단 고정 정보

- 이름
- 현재 시즌
- 주 소속 스쿼드
- 등번호
- 학년
- 주 포지션
- 팀 등록 상태
- 현재 참가 가능 상태

#### 영역

1. 요약
2. 전체 기록
3. 훈련·경기
4. 성장·피지컬
5. 컨디션·부상
6. 상담·피드백
7. 소속·정보

신체 측정, 부상, 세션과 피드백은 같은 선수로 연결하되 기본 정보 편집과 분리합니다.

#### 정보 누락 표시

- 필수 정보가 없으면 상세 상단에 누락 항목을 표시합니다.
- 선택 정보가 없는 경우 경고로 표시하지 않습니다.
- 연락처나 계정이 없는 것은 선수 운영을 막지 않습니다.

### 8.5 PL-07 소속·등번호 변경

#### 입력

- 변경 종류: 공식 스쿼드 / 등번호 / 주 포지션
- 현재 값
- 새 값
- 적용일
- 변경 사유

#### 처리

- 현재 기록의 종료일을 적용일 전날로 설정
- 새 기록을 적용일부터 생성
- 과거 세션은 당시 기록을 유지
- 기간이 겹치면 저장 차단
- 등번호가 겹치면 해당 선수와 기간을 보여주고 저장 차단

### 8.6 PL-08 선수 등록 종료

#### 입력

- 종료일
- 종료 사유: 졸업, 이적, 방출, 자진 퇴단, 팀 이동, 기타
- 내부 메모(선택)
- 향후 일정 대상에서 제외 확인

#### 확인 내용

- 종료 후에도 과거 기록은 유지됨
- 종료일 이후 일정에서 제외됨
- 선수 계정은 자동 삭제되지 않음

종료 행동은 `선수 삭제`로 표현하지 않습니다.

### 8.7 TM-01 팀 관리 개요

팀 홍보 정보나 경기 성적을 보여주는 대시보드가 아닙니다.

#### 보여줄 정보

- 현재 팀과 운영 상태
- 현재 시즌과 기간
- 공식 스쿼드별 인원
- 등록 대기 선수
- 필수 정보 누락
- 등번호·소속 충돌
- 초대 대기·권한 미설정 스태프
- 다음 시즌 준비 상태

#### 주 행동

상태에 따라 하나만 제공합니다.

- 팀 설정이 덜 됨: `설정 계속하기`
- 현재 시즌 없음: `시즌 만들기`
- 시즌 운영 중: `시즌·스쿼드 관리`
- 다음 시즌 준비 중: `다음 시즌 명단 정리`

### 8.8 TM-02 시즌·스쿼드

#### 시즌 목록

- 시즌 이름
- 기간
- 상태
- 스쿼드 수
- 등록 선수 수
- 수정일

#### 공식 스쿼드

- 이름
- 연령 구분
- 표시 순서
- 현재 인원
- 담당 스태프
- 상태

#### 제한

- 운영 중 시즌은 하나만 가능
- 종료된 시즌은 읽기 전용
- 선수가 배정된 스쿼드는 삭제하지 않고 사용 종료
- 스쿼드 이름 변경 시 기존 ID와 과거 기록 유지

### 8.9 TM-03 시즌 전환

데이터 연결과 졸업·진학 처리는 [선수 생애주기·시즌 전환·진학 데이터 정책](./PLAYER_LIFECYCLE_DATA_POLICY.md)을 따릅니다.

#### 선수별 선택

- 다음 시즌 등록
- 졸업
- 이적·퇴단
- 결정 보류

#### 다음 시즌 입력

- 공식 스쿼드
- 학년
- 주 포지션
- 등번호
- 학교 확인

#### 완료 조건

- 모든 선수 처리 상태 선택
- 스쿼드 필수값 입력
- 등번호 충돌 해결
- 종료 선수의 종료일과 사유 입력
- 팀 매니저 또는 감독의 최종 확인

#### 데이터 상태 표시

- 이어짐: 선수 식별자, 이름·생년월일, 팀 입단 이력
- 다시 확인: 연락처, 비상 연락처, 학교, 주 포지션
- 새로 입력: 스쿼드, 학년, 등번호, 시즌 등록 상태
- 과거 조회만: 지난 시즌 일정·참가·측정·평가

### 8.10 TR-01~03 졸업·진학 데이터 인계

- 졸업 선수는 현재 명단에서 제외하고 `졸업생` 목록에 보관합니다.
- 진학·이적 인계는 수신 기관, 제공 목적, 범위, 이용 기간과 동의 상태를 포함합니다.
- 수신팀은 출신팀 확인본을 읽기 전용으로 보고 자체 현재 프로필을 별도로 만듭니다.
- 다른 구단 선수는 이름·생년월일 검색으로 찾을 수 없습니다.
- 의료·민감 정보는 기본 인계에서 제외합니다.
- 인계 화면은 작성 중, 동의 대기, 출신팀 확인, 수신팀 검토, 연결 완료, 거절, 만료, 철회 상태를 제공합니다.

한 사람에게 여러 역할을 주기보다 주 역할 하나와 담당 범위를 지정합니다. 추가 권한이 필요한 경우 예외 권한을 남발하지 않고 역할 정책을 먼저 검토합니다.

## 9. 상태와 전환

### 9.1 선수 팀 등록

```text
등록 대기 → 활동 중 → 일시 중지 → 활동 중
                   └────────────→ 종료
```

- `등록 대기 → 활동 중`: 시즌, 스쿼드, 학년과 주 포지션 확인
- `활동 중 → 일시 중지`: 적용일과 사유 필요
- `일시 중지 → 활동 중`: 복귀일 필요
- `활동 중·일시 중지 → 종료`: 종료일과 종료 사유 필요
- 종료 복구: 구단 관리자 또는 허용된 팀 매니저만 가능

### 9.2 시즌

```text
준비 중 → 운영 중 → 종료
```

이전 상태로 직접 되돌리지 않습니다. 잘못 종료한 시즌은 구단 관리자의 정정 절차를 사용합니다.

## 10. 입력과 오류 처리

모든 예외는 [팀·선수 관리 예외 처리 정책](./TEAM_PLAYER_MANAGEMENT_EXCEPTION_POLICY.md)에 따라 `차단`, `확인 후 진행`, `등록 대기`, `자동 복구` 중 하나로 처리합니다. 화면은 문제 항목, 저장 여부, 영향과 다음 행동을 함께 알려야 합니다.

### 저장 차단

- 필수값 없음
- 미래 생년월일
- 시즌 시작일이 종료일보다 늦음
- 같은 기간에 주 소속 스쿼드가 두 개 이상
- 같은 스쿼드·기간에 등번호 중복
- 권한 없음

### 경고 후 진행 가능

- 일반적인 유소년 연령 범위를 벗어남
- 입단일이 현재 시즌 시작일보다 오래됨
- 같은 이름의 선수가 존재함
- 연락처 없음
- 사진 없음

### 저장 상태

- 저장 중
- 저장됨
- 저장하지 못함
- 다른 사용자가 먼저 수정함

저장 실패와 권한 변경 시 작성 중인 값은 유지합니다. 같은 요청을 다시 시도해도 선수나 시즌 등록이 중복 생성되지 않아야 합니다. 일괄 작업은 적용 가능·제외·충돌 대상을 실행 전에 보여줍니다.

오류 문구에는 문제가 생긴 항목과 해결 방법을 같이 표시합니다.

## 11. 권한 적용

- 권한이 없는 메뉴와 항목은 숨기기만 하지 않고 API에서도 차단합니다.
- 담당 스쿼드 밖의 선수는 검색 결과와 자동 완성에 표시하지 않습니다.
- 팀 매니저는 의료 상세를 볼 수 없습니다.
- 코치는 연락처를 기본적으로 볼 수 없습니다.
- 메디컬은 참가 제한을 관리하지만 선수 소속을 변경할 수 없습니다.
- 중복 병합과 종료 시즌 정정은 구단 관리자만 가능합니다.

세부 권한은 [팀·선수 등록 및 관리 정책](./TEAM_PLAYER_MANAGEMENT_POLICY.md#15-역할과-권한)을 따릅니다.

## 12. 문구 기준

- 화면 제목은 실제 업무명으로 씁니다: `선수 등록`, `시즌·스쿼드`, `등록 종료`.
- 상태는 뜻이 분명한 말만 사용합니다: `등록 대기`, `활동 중`, `일시 중지`, `종료`.
- `스마트`, `인사이트`, `최적화`, `솔루션`처럼 실제 작업을 설명하지 않는 말은 사용하지 않습니다.
- `자동으로 관리합니다` 대신 어떤 값이 언제 바뀌는지 설명합니다.
- 삭제되지 않는 작업을 `삭제`라고 쓰지 않습니다.
- 선수 책임으로 읽히는 오류 문구를 사용하지 않습니다.

## 13. 반응형 범위

### 데스크톱

- 등록, 일괄 등록, 시즌 전환과 권한 관리를 모두 지원합니다.
- 선수 비교와 일괄 작업은 표를 기본으로 합니다.

### 모바일

1차 구현에서는 다음만 지원합니다.

- 선수 목록 조회와 검색
- 선수 기본 정보 조회
- 현재 소속과 참가 가능 상태 확인
- 포지션과 운영 그룹의 간단한 수정

일괄 등록, 시즌 전환, 중복 병합과 권한 변경은 데스크톱에서 진행합니다.

## 14. 완료 조건

### 기능

- [ ] 팀과 시즌이 분리되어 있다.
- [ ] 선수 계정 없이 선수를 등록할 수 있다.
- [ ] 선수 개별 등록을 완료할 수 있다.
- [ ] 명단 파일을 검사하고 선택적으로 등록할 수 있다.
- [ ] 중복 후보를 기존 선수와 연결하거나 신규 등록할 수 있다.
- [ ] 시즌, 스쿼드, 학년, 포지션과 등번호 이력을 확인할 수 있다.
- [ ] 다음 시즌 명단을 만들 수 있다.
- [ ] 등록 종료 후에도 과거 기록을 볼 수 있다.
- [ ] 역할과 담당 범위에 따라 접근이 제한된다.
- [ ] 주요 변경 기록을 조회할 수 있다.

### 화면

- [ ] 현재 팀·시즌·스쿼드 범위를 확인할 수 있다.
- [ ] 주 행동이 화면마다 하나만 강조된다.
- [ ] 필수 정보와 선택 정보가 구분된다.
- [ ] 빈 상태, 오류, 권한 없음과 읽기 전용 상태가 정의되어 있다.
- [ ] 차단, 확인 후 진행, 등록 대기와 자동 복구가 구분되어 있다.
- [ ] 색만으로 상태를 구분하지 않는다.
- [ ] 320px 모바일 폭과 일반 데스크톱 폭에서 내용이 잘리지 않는다.

### 데이터

- [ ] 과거 시즌 값이 현재 값으로 덮어써지지 않는다.
- [ ] 주 소속과 등번호 기간이 겹치지 않는다.
- [ ] 세션 기록이 있는 선수는 물리적으로 삭제되지 않는다.
- [ ] 구단 밖의 선수 정보가 검색되지 않는다.
- [ ] 변경 실행자와 시각이 기록된다.
- [ ] 저장·파일 등록 재시도로 중복 데이터가 생기지 않는다.
- [ ] 동시 수정이 다른 사용자의 변경을 조용히 덮어쓰지 않는다.

## 15. 개발 순서

1. 데이터 구조와 이전 계획
2. 팀·시즌·스쿼드 API
3. 선수 원본·팀 등록·시즌 등록 API
4. 선수단 목록과 개별 등록
5. 선수 상세와 소속 이력
6. 일괄 등록과 중복 확인
7. 시즌 전환
8. 스태프 권한과 변경 기록
9. 세션·GPS·메디컬 데이터 연결

기존 샘플 화면을 새 API에 바로 연결하지 않습니다. 먼저 데이터 이전 기준과 선수 중복 방지 규칙을 적용한 뒤 화면을 교체합니다.
