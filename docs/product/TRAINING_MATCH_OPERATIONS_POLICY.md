> 상태: 기획 검토용 0.1
> 최종 수정: 2026-08-23
> 기준 사용자: 한국 유소년 축구팀 감독, 코치, 팀 매니저
> 우선 플랫폼: Coach Desktop / 현장 실행은 Coach Mobile 보조
> 상위 기획: [BASE11 제품 기획서](./PRODUCT_SPEC.md)
> 선수단 기준: [선수단 운영 정책](./SQUAD_OPERATIONS_POLICY.md)

## 1. 목적

지도자가 훈련과 경기를 등록하고, 참가 대상을 준비하고, 현장에서 실제 참가와 실행 내용을 기록하고, 종료 후 결과를 다음 계획에 연결하는 전 과정을 하나의 흐름으로 관리합니다.

이번 범위는 지도자와 팀 매니저의 운영 업무를 우선합니다. 선수·학부모가 보는 일정·공지 화면은 데이터 공개 범위만 정의하고 별도 화면 설계는 후순위로 둡니다.

## 2. 확정 원칙

1. `일정`, `훈련 세션`, `경기`는 연결되지만 서로 다른 기록입니다.
2. 일정의 `예상 대상`과 세션의 `실제 참가자`를 분리합니다.
3. 경기의 `대상 스쿼드`, `경기 엔트리`, `실제 출전`을 분리합니다.
4. U17 선수가 U18 훈련·경기에 참가해도 공식 소속은 자동 변경하지 않습니다.
5. 게시 전 초안만 삭제할 수 있습니다. 게시 이후에는 취소·연기·정정으로 기록을 남깁니다.
6. 훈련 템플릿을 복제할 때 계획만 복제하고 실제 참가자, GPS, RPE, 메모와 결과는 복제하지 않습니다.
7. 경기 결과는 점수, 득점 기록, 출전 기록이 서로 맞아야 완료할 수 있습니다.
8. 저장 실패와 통신 재시도는 같은 훈련·경기·이벤트를 중복 생성하지 않아야 합니다.
9. 완료 후 수정은 일반 편집이 아니라 사유를 남기는 `정정`으로 처리합니다.
10. 화면에는 항상 현재 팀, 시즌, 스쿼드 범위, 일정 상태를 표시합니다.

## 3. 용어와 기록 단위

| 용어 | 의미 | 기록 기준 |
| --- | --- | --- |
| 일정 | 캘린더에서 관리하는 시간·장소·대상·공개 정보 | 팀 + 시작 시각 |
| 훈련 세션 | 훈련 목적, 블록, 실제 참가, 부하와 회고 | 일정 ID + 세션 ID |
| 경기 | 상대, 대회, 장소, 홈·원정, 결과를 가진 경기 단위 | 경기 ID |
| 예상 대상 | 일정 생성 시 스쿼드·그룹·개인 규칙으로 계산한 선수 | 일정 대상 규칙 |
| 실제 참가자 | 훈련 또는 경기에 실제 참여한 선수 | 선수 ID + 세션 ID |
| 경기 엔트리 | 경기에 등록한 선수 명단 | 경기 ID + 선수 ID |
| 라인업 | 선발, 벤치, 포지션과 역할 | 경기 ID + 엔트리 ID |
| 실제 출전 | 선발·교체·퇴장으로 계산된 출전 구간 | 경기 ID + 선수 ID |
| 훈련 블록 | 시간, 강도, 그룹, 담당자, 코칭 포인트를 가진 실행 단위 | 세션 ID + 순서 |
| 경기 이벤트 | 득점, 교체, 카드, 부상, 전술 변경 등 시점 기록 | 경기 ID + 경기 시각 |
| 정정 | 완료된 기록을 사유와 함께 고치는 작업 | 변경 기록 ID |

## 4. 데이터 관계

```text
팀
└─ 시즌
   ├─ 일정
   │  ├─ 예상 대상 규칙
   │  └─ 공개본·변경 이력
   ├─ 훈련 세션
   │  ├─ 훈련 블록
   │  ├─ 실제 참가자
   │  ├─ 선수별 GPS·RPE·참가 제한
   │  └─ 코치 메모·피드백
   └─ 경기
      ├─ 경기 엔트리·라인업
      ├─ 실제 출전·경기 이벤트
      ├─ 점수·결과
      └─ GPS·총평·피드백
```

- 일정은 훈련 세션 또는 경기 하나와 연결합니다.
- 경기 하나를 여러 스쿼드 캘린더에 복제하지 않고 대상 범위만 여러 개 지정합니다.
- 훈련·경기 기록은 당시의 선수 소속 이력을 참조하며 현재 소속으로 다시 계산하지 않습니다.

## 5. 상태 모델

### 5.1 훈련 상태

| 상태 | 의미 | 가능한 주 행동 |
| --- | --- | --- |
| 작성 중 | 필수 정보나 계획이 아직 완성되지 않음 | 계속 작성, 초안 삭제 |
| 예정 | 지도자 운영 일정으로 확정됨 | 참가자·계획 확인 |
| 진행 중 | 현장에서 실제 참가와 실행을 기록 중 | 참가자 확정, 빠른 메모 |
| 기록 정리 | 훈련은 끝났으나 참가·부하·메모 확인이 남음 | 누락 확인, 완료 처리 |
| 완료 | 운영 기록이 확정됨 | 조회, 정정 요청, 복제 |
| 취소 | 실행하지 않은 일정 | 사유 조회, 다시 만들기 |

기본 전환:

```text
작성 중 → 예정 → 진행 중 → 기록 정리 → 완료
   └────→ 취소       └──────→ 취소
```

### 5.2 경기 상태

| 상태 | 의미 | 가능한 주 행동 |
| --- | --- | --- |
| 작성 중 | 경기 기본 정보가 미완성 | 계속 작성, 초안 삭제 |
| 예정 | 일정이 확정됨 | 엔트리·라인업 준비 |
| 진행 중 | 실제 출전과 경기 이벤트 기록 중 | 이벤트 기록 |
| 결과 확인 | 경기 종료 후 점수·출전·이벤트를 검토 중 | 결과 검토 |
| 완료 | 최종 경기 기록이 확정됨 | 조회, 정정 요청 |
| 연기 | 기존 시작 시각이 취소되고 새 일정이 필요함 | 새 일시 확정 |
| 취소 | 경기를 치르지 않음 | 취소 사유 조회 |
| 중단 | 시작했지만 정상 종료하지 못함 | 중단 결과 처리 |

```text
작성 중 → 예정 → 진행 중 → 결과 확인 → 완료
   └────→ 취소   ├────→ 중단
          예정 ──└────→ 연기 → 예정
```

### 5.3 준비 상태는 주 상태와 분리

상태가 너무 많아지는 것을 막기 위해 다음 값은 별도 준비 상태로 표시합니다.

- 참가자: 미확인 / 확인 중 / 확정
- 훈련 계획: 없음 / 작성 중 / 완료
- 경기 엔트리: 미작성 / 작성 중 / 확정
- 라인업: 미작성 / 작성 중 / 확정
- GPS·RPE: 미연결 / 일부 연결 / 완료 / 사용 안 함
- 피드백: 없음 / 작성 중 / 완료

## 6. 훈련 등록 정책

### 6.1 필수 정보

- 팀과 시즌
- 훈련명
- 날짜, 시작 시간, 예상 시간
- 장소
- 예상 대상 하나 이상
- 운영 담당자 한 명 이상

### 6.2 계획 완료 전 권장 정보

- 훈련 목적
- 전체 강도
- 훈련 블록 하나 이상
- 블록별 시간, 그룹, 담당자와 코칭 포인트
- 준비물과 내부 운영 메모

기본 정보만 있으면 `작성 중`으로 저장할 수 있습니다. `예정`으로 확정할 때는 예상 대상과 담당자가 반드시 있어야 합니다. 훈련 블록이 없어도 일정 확정은 가능하지만 준비 상태를 `계획 없음`으로 표시합니다.

### 6.3 대상 구성

대상은 다음 순서로 계산합니다.

```text
공식 스쿼드 + 운영 그룹 + 개별 추가 - 개별 제외 = 예상 대상
```

- 같은 선수가 여러 규칙에 포함되면 한 명으로 합칩니다.
- 제외가 추가보다 우선합니다.
- 공식 소속이 다른 선수는 `상위 합류`, `임시 합류`, `개인 추가` 중 하나의 참가 방식을 지정합니다.
- 등록 종료일 이후 선수와 유효한 참가 제한이 있는 선수는 자동 포함하지 않고 확인 대상으로 표시합니다.

### 6.4 템플릿

템플릿에 포함:

- 훈련명
- 목적과 강도
- 블록 구성
- 기본 장소
- 담당 역할

템플릿에 포함하지 않음:

- 날짜와 시간
- 실제 참가자
- 선수별 제한·상태
- GPS·RPE
- 코치 메모와 피드백

삭제된 스태프나 운영 그룹이 템플릿에 남아 있으면 적용 전에 다시 지정합니다.

## 7. 훈련 운영 정책

### 7.1 훈련 전

지도자는 다음 항목을 우선 확인합니다.

1. 예상 대상과 추가·제외 선수
2. 부상·재활·참가 제한 선수
3. 장소·시간 충돌
4. 담당 스태프와 미배정 블록
5. 계획 시간과 블록 시간의 차이

### 7.2 훈련 시작

- `훈련 시작` 시 예상 대상을 실제 참가자 초안으로 가져옵니다.
- 불참, 지각, 조기 종료, 제한 참여와 개인 추가를 기록할 수 있습니다.
- 참가 방식과 사유는 선수별로 남깁니다.
- 예상 대상 변경이 아니라 실제 참가 기록으로 저장합니다.

### 7.3 훈련 중

- 블록 시작·완료 시간을 빠르게 기록할 수 있습니다.
- 계획 순서와 시간을 바꾸면 실제 실행값을 별도로 남깁니다.
- 위험 선수, 통증, 제한 참여는 메디컬 상세 없이 운영상 필요한 결과만 표시합니다.
- 통신이 불안정하면 현장 기록을 기기에 임시 저장하고 연결 후 같은 기록으로 동기화합니다.

### 7.4 훈련 종료

`기록 정리`로 전환할 때 확인:

- 실제 참가자
- 참가 방식과 제외 사유
- 실제 훈련 시간
- 실행한 블록과 생략한 블록
- 선수별 RPE 또는 사용 안 함
- GPS 연결 여부
- 코치 메모와 후속 조치

다음 조건이 충족되면 `완료`할 수 있습니다.

- 실제 참가자가 한 명 이상이거나 `참가자 없음` 사유가 있음
- 실제 종료 시각 또는 총 시간이 있음
- 필수 후속 조치가 담당자에게 배정됨

GPS·RPE와 피드백 누락은 완료를 막지 않지만 데이터 완성도를 별도로 표시합니다.

## 8. 경기 등록 정책

### 8.1 필수 정보

- 팀과 시즌
- 경기 구분: 공식전 / 친선전 / 연습경기
- 대회·리그 또는 친선전 명칭
- 상대 팀 또는 `상대 미정`
- 날짜와 킥오프 시간
- 홈 / 원정 / 중립
- 경기장 또는 `장소 미정`
- 대상 스쿼드
- 담당 지도자

### 8.2 선택 정보

- 라운드·조·경기 번호
- 집결 시각과 장소
- 이동 계획
- 유니폼
- 엔트리 마감 시각
- 경기 시간 규칙, 교체 인원과 재교체 허용 여부
- 내부 준비 메모

`상대 미정`과 `장소 미정`은 토너먼트 대진 전 일정에서 허용합니다. 다만 엔트리·이동 준비 상태에는 확인 필요로 표시합니다.

### 8.3 중복 경기

같은 팀·대회·상대·킥오프가 일치하면 기존 경기 후보를 먼저 보여줍니다. 사용자가 기존 경기로 이동하거나 별도 경기임을 확인하기 전까지 새 경기를 확정하지 않습니다.

## 9. 경기 준비와 운영 정책

### 9.1 경기 엔트리

- 대상 스쿼드는 후보 범위이고 엔트리는 실제 등록 명단입니다.
- 다른 공식 스쿼드 선수를 엔트리에 넣어도 공식 소속은 유지합니다.
- 등록 종료, 출전 정지, 유효한 참가 제한, 중복 등번호는 선수별로 표시합니다.
- 경기 규정의 최대 인원과 마감 시각을 저장한 경우 이를 기준으로 검증합니다.

### 9.2 라인업

- 선발, 벤치, 제외와 주장·골키퍼 역할을 구분합니다.
- 축구 기본값은 선발 11명이지만 경기 규칙이 다르면 조정할 수 있습니다.
- 포메이션은 선택 정보이며 라인업 확정을 막지 않습니다.
- 엔트리에 없는 선수는 라인업에 넣을 수 없습니다.

### 9.3 경기 중·경기 후 기록

1차 범위는 실시간 중계가 아니라 지도자용 빠른 기록입니다.

- 득점·자책골·실점
- 교체 투입·교체 아웃
- 경고·퇴장
- 부상·조기 종료
- 전술 변경과 내부 메모

경기 종료 후 다음을 확인합니다.

- 정규 시간 점수
- 연장 점수
- 승부차기 결과
- 몰수·중단 여부
- 선발과 교체 기록
- 선수별 출전 시간
- 경기 이벤트와 점수 일치
- 감독 총평과 후속 조치

### 9.4 결과 완료

다음 조건을 만족해야 `완료`할 수 있습니다.

- 결과 유형이 선택됨: 승 / 무 / 패 / 중단 / 몰수
- 우리 팀과 상대 팀 점수가 있음. 중단·몰수는 별도 사유로 대체 가능
- 선발·교체 기록으로 출전 시간을 계산할 수 있거나 수동 확인됨
- 득점 이벤트 수와 점수 차이가 있으면 차이 사유를 확인함

## 10. 변경·취소·연기·삭제

### 10.1 게시 전

- 작성 중 일정은 자유롭게 편집할 수 있습니다.
- 연결된 참가·부하·피드백 기록이 없는 초안만 삭제할 수 있습니다.

### 10.2 예정 상태

시간, 장소, 대상, 담당자를 바꾸면 저장 전에 영향 대상을 보여줍니다.

- 영향 선수 수
- 영향 스태프 수
- 장소·일정 충돌
- 이미 확정한 엔트리·라인업
- 공개본 재확인 필요 여부

### 10.3 진행 중

- 기본 일정 정보를 직접 바꾸지 않고 현장 변경으로 기록합니다.
- 경기 상대와 대회는 진행 중 변경할 수 없습니다.
- 참가자·출전·이벤트는 실제 기록으로 수정할 수 있습니다.

### 10.4 완료 후

- 일반 편집을 잠급니다.
- 정정 항목, 이전 값, 새 값과 사유를 기록합니다.
- 경기 점수와 출전 기록 정정은 감독 또는 구단 관리자 권한을 요구합니다.

### 10.5 취소

- 취소일, 취소 사유, 실행 여부를 기록합니다.
- 과거 변경과 공개 이력은 유지합니다.
- 이미 실행 기록이 있으면 `취소`가 아니라 `중단` 또는 `완료 후 정정`을 사용합니다.

### 10.6 경기 연기

- 원래 킥오프와 연기 사유를 유지합니다.
- 새 일정이 미정이면 `연기` 상태로 둡니다.
- 새 일정이 확정되면 같은 경기 ID의 새 킥오프 이력을 추가하고 `예정`으로 돌아갑니다.
- 기존 엔트리는 유지하되 선수 등록·제한 상태를 다시 검사합니다.

## 11. 권한

| 작업 | 기본 권한 |
| --- | --- |
| 훈련 초안 작성 | 감독, 코치, 팀 매니저 |
| 훈련 일정 확정 | 감독, 팀 매니저, 허용된 코치 |
| 실제 참가자·현장 메모 | 배정된 지도자 |
| 훈련 완료 | 담당 코치, 감독 |
| 경기 등록 | 감독, 팀 매니저 |
| 엔트리·라인업 확정 | 감독, 허용된 코치 |
| 경기 결과 완료 | 감독 |
| 완료 기록 정정 | 감독, 구단 관리자 |
| 참가 제한 상세 | 허용된 메디컬·지도자 |

- 담당 범위 밖 스쿼드 선수는 검색 결과에도 노출하지 않습니다.
- 권한이 편집 중 회수되면 저장을 막되 입력은 유지합니다.

## 12. 변경 기록

다음 작업은 반드시 기록합니다.

- 일정 생성·확정·시간·장소·대상 변경
- 참가자 추가·제외와 사유
- 훈련 블록의 주요 변경
- 경기 엔트리·라인업 확정과 변경
- 경기 점수·이벤트·출전 기록 변경
- 취소·연기·중단·완료
- 완료 후 정정
- 공개 범위 변경

## 13. 데스크톱과 현장 모바일 역할

### Coach Desktop

- 일정과 마이크로사이클 계획
- 훈련 블록과 템플릿 편집
- 복수 스쿼드·운영 그룹 대상 구성
- 경기 엔트리·라인업 편집
- 경기 결과 검토와 정정
- 변경 기록과 데이터 완성도 확인

### Coach Mobile

- 오늘 훈련·경기 확인
- 실제 참가자와 제한 선수 확인
- 빠른 불참·지각·제한 참여 기록
- 경기 이벤트와 교체 빠른 기록
- 현장 메모 임시 저장
- 종료 후 최소 확인

모바일에서 복잡한 대량 편집, 템플릿 관리, 완료 기록 정정은 제공하지 않습니다.

## 14. 1차 범위에서 제외

- 선수·학부모 전용 UI
- 협회·대회 시스템 자동 엔트리 제출
- 실시간 중계와 외부 공개 스코어보드
- 심판 공식 기록 대체
- 영상 자동 이벤트 추출
- AI 훈련 추천과 자동 라인업 추천
- 회계, 차량과 숙박 예약

## 15. 별도 결정이 필요한 항목

- 대회별 엔트리·교체 규칙 템플릿
- 경기 결과의 협회 공식 기록 대조 방식
- 현장 오프라인 저장 기간과 기기 분실 대응
- 선수·학부모 공개본의 최종 필드 범위
- 의료·참가 제한 정보의 화면별 마스킹 수준

이 항목은 1차 UI 구조를 막지 않지만 외부 공개·대회 연동 전에는 확정해야 합니다.
